# Промпт агента

```text
Задание integration. Ты единственный интегратор этого набора работ. Прочитай AGENTS.md, план, контракт и отчёты агентов. Проверь origin и отсутствие работы с upstream. Все task-ветки должны происходить от нашей актуальной main; не брать исходный VS Code заново.

До начала интеграции запиши в собственный docs/agent-reports/integration.md task-id, ветки/коммиты и текущих владельцев. При отсутствии готового task-коммита не угадывай результат и не включай пустые файлы в релиз. Не переключай checkout работающего агента. Собери изменения в отдельном integration checkout/ветке; не переносить node_modules/out/.build.

Только ты правишь общие entrypoints, DI/IPC wiring, product.json, built-in allowlist, build scripts и root dependencies/lockfiles. Подключи PDF backend и UI по v1; изменения контракта согласуй с обоими владельцами до правки. Сначала просматривай каждый diff и тесты; сохраняй авторство и настройки hooks/signing/noreply. MCP audit — материал для последующей работы, не готовая реализация удаления.

Сначала зафиксируй состав релизного пакета в отчёте и накопи несколько готовых изменений/задач. Не запускай полную сборку и релиз после каждой правки, коммита, завершения одного агента или сообщения «дальше». До готовности пакета выполняй целевые проверки; затем один общий цикл приёмки из development-plan.md и раздела «Сборки пакетами» в AGENTS.md. Переиспользуй успешные проверки при неизменных входных данных. Повторяй только затронутые этапы после исправлений; досрочную полную сборку обоснуй конкретным дефектом, требующим packaged app, или явным запросом пользователя. Документы/отчёты/промпты не требуют сборки или перепаковки ради SHA. Тяжёлые проверки/сборка последовательно, только один владелец общего app output. Native smoke обязательно включает пустую языковую поставку, shell Tasks exit0, zsh/bash, Git, completion, manual formatting, VSIX install/update/uninstall, отсутствие удалённых AI действий и реальные PDF с проверкой текста/страниц. Не переносить тестовые настройки в профиль пользователя.

Перед публикацией: privacy guard, ASAR refresh после deep signing, outer signing/verify, аудит ZIP. Проверенную интеграцию доведи до origin/main обычным merge/fast-forward, без force; при PR проверь merged state. Публикуй prerelease на весь проверенный пакет изменений приложения, сверяй тег фактически собранного исходного коммита и digest asset. Не оставляй готовые этапы только в task-ветках. Непройденные проверки — блокируют релиз, но не мешают зафиксировать честный промежуточный отчёт. Обнови план и docs/myself-ide.md по фактам; не обещай удаление всех AI частей или поддержку всех платформ без проверки.
```
