# Задание: визуал Nerded Code / Calmer Studio

Решение владельца от 6 ноября 2026: рабочее имя **Nerded Code**, выбран **Calmer Studio · Оригинал** с **цветными vscode-icons**. Реализовать этот вариант по [полной спецификации](../nerded-code-visual-spec.md). HTML-референсы находятся в `docs/design/references/`; во втором icon-варианте стоит `hidden` только из-за исходного состояния карусели. Монохромный вариант не выбран.

Это активное новое визуальное задание. Старые пункты «бренд позже» и неопределённый «визуальный ремастер» уточнены этим выбором. Статус: готово к назначению, реализация не подтверждена. Владельцы ещё не назначены этим документом.

## Перед стартом

Прочитай AGENTS.md, docs/development-plan.md, docs/nerded-code-visual-spec.md, актуальные docs/agent-reports и инструкции modernUI. Проверь git status и занятые области. Работай в выделенном checkout от актуального main; не переключай общий каталог. Не запускай других агентов этим промптом.

С текущим интегратором выбери один scope: `nerded-calm-theme-icons`, `nerded-calm-layout` или `nerded-calm-integration`. Запиши владельца и точный набор файлов в собственном отчёте до правок. Последний scope — только для интегратора. Не дублируй текущего владельца UI и не меняй чужие claims.

## Сделать

- Перенести утверждённую палитру и иерархию поверхностей в настоящую тему/workbench; лёгкие радиусы, компактные файлы/вкладки/терминал, без стекла и плавающих островов.
- Подключить полный цветной vscode-icons локально через штатную icon theme. Служебные кнопки оставить сдержанными.
- Дать новому профилю выбранный пресет, существующему — видимое применение без сброса личных настроек. Общие defaults и бренд подключает интегратор.
- Применить рабочее имя Nerded Code в пользовательском брендинге без автоматического переименования data paths, storage keys, extension IDs и репозитория.
- Проверить реальное приложение по критериям ТЗ и подготовить снимки для сравнения с выбранными вариантами.

## Сохранить границы

Первый пакет остаётся локальным; Remote SSH/server и GitHub login/catalog не подключать ради макета. Ручной git/ssh сохранить. Не возвращать AI, Sessions, Command Palette и фоновые загрузки. Логотип/маскот не утверждены и в этот scope не входят. HTML/демо-данные не переносить вместо штатных редактора и терминала.

## Завершение

Целевые проверки по своей области, отчёт с результатами и ограничениями, ветка/коммит и точные подключения для интегратора. Общие product.json/build/entrypoints меняет только интегратор. Не собирать отдельный релиз после каждого визуального шага; полный цикл — один на общий пакет. Не считать документацию или неподключённую тему готовым визуалом приложения.
