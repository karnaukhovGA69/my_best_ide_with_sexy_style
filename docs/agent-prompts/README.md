# Запуск параллельных агентов

Открой наш репозиторий в отдельных рабочих каталогах от актуального main. Каждому агенту дай содержимое одного блока из файла ниже. Одно задание — один агент. Имена веток рекомендуемые; agent должен проверить, что ветка не занята. Эти файлы не запускают агентов автоматически.

| Агент | Файл | Когда запускать |
| --- | --- | --- |
| A — документы | [01-documents-ui.md](01-documents-ui.md) | Сейчас, независимо от backend; тестировать mock |
| B — PDF | [02-pdf-export.md](02-pdf-export.md) | Сейчас, по фиксированному DTO |
| C — терминальный AI | [03-ai-terminal-cleanup.md](03-ai-terminal-cleanup.md) | Сейчас, отдельная область |
| D — MCP аудит | [04-mcp-audit.md](04-mcp-audit.md) | Сейчас, только чтение и собственный отчёт |
| Интегратор | [05-integration.md](05-integration.md) | Один на весь набор; объединение после готовности результатов |

A/B/C/D не делят рабочий каталог. Если доступны только два агента, сначала A+B, потом C+D. Полные сборки запускает только интегратор на накопленный релизный пакет из нескольких изменений. Готовность отдельного агента не запускает сборку или релиз: агент передаёт код и результаты целевых проверок, интегратор проверяет весь пакет вместе. Документационные правки обходятся без сборки. Основные правила — в корневом AGENTS.md; распределение файлов и приёмка — в docs/development-plan.md.
