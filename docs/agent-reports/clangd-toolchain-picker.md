# Выбор clangd для папки проекта

База `8ee7ab8c965`, ветка `codex/clangd-toolchain-picker`, код `3e47e839e0cb758646eb6cfd793d6d9106dd786c`. Реализация и тесты находятся в `src/vs/workbench/contrib/myselfToolchain`. Используется существующая регистрация десктопной contribution. Интегратору достаточно перенести коммит и включить сценарий в пакетную приёмку.

## Контракт клиента

Проверен локальный `llvm-vs-code-extensions.vscode-clangd` версии 0.6.0. SHA-256 `out/bundle.js` — `55e37b5a799c5e2702a9d20512a9dda90a793e74e01588feca0e5aecf75afd2d`. Манифест задаёт строковый `clangd.path` с `machine-overridable` и значением по умолчанию `clangd`, логический `clangd.checkUpdates` со стандартной областью `window` и логический `clangd.useScriptAsExecutable` с `machine-overridable`. Оба флага по умолчанию выключены. Манифест перечисляет языковые события активации и запрещает работу в недоверенных папках.

При инициализации экземпляр клиента читает `workspace.getConfiguration("clangd")` без URI и разрешает переменные в строковых значениях. `resolveClangdPath` сохраняет выбранный путь. Код запуска учитывает `useScriptAsExecutable` при выборе shell. При доступном абсолютном пути и выключенной проверке обновлений этап `prepare` пропускает её. Если при следующей инициализации путь недоступен, восстановление может запросить сведения о релизе с GitHub даже при выключенном `checkUpdates`. Подтверждение сообщает оба последствия до записи.

В `WorkbenchState.FOLDER` `ConfigurationEditing.getConfigurationFileResource` разрешает `WORKSPACE_FOLDER` с URI папки в её `.vscode/settings.json`. `configurationService.writeConfigurationValue` дожидается записи и вызывает `reloadWorkspaceFolderConfiguration`. `onWorkspaceFolderConfigurationChanged` применяет модель этой папки одновременно как workspace configuration. Так новая настройка становится видна при чтении без URI. Окно `.code-workspace` имеет другой порядок слоёв и исключено даже с одной папкой.

## Поведение

- **Configure Project clangd…** в меню Terminal и действий панели Files. Требуется доверенное десктопное окно с одной напрямую открытой локальной папкой. Действие проверяет регистрацию локального клиента версии 0.6.0 и владельца, тип и область трёх настроек. Оба эффективных флага должны быть `false`. Приоритетные path overrides из политики или памяти блокируют выбор.
- Пользователь выбирает один обычный локальный файл с буквальным абсолютным путём. Родительская папка, `.vscode` и `settings.json` проверяются по метаданным после подтверждения. Окно показывает прежнее эффективное значение, прежнее значение папки, новый путь и целевой файл. Проверка доверия, папки, провайдера, метаданных файла и снимка настроек повторяется перед вызовом записи.
- Выполняется одна штатная запись `clangd.path` с целью `WORKSPACE_FOLDER`. После записи действие проверяет значение без URI и сообщает о расхождении, если оно есть. У действия нет вызовов запуска, обновления, установки или активации клиента.

Метаданные фиксируют тип и состояние файла во время проверки. Исполняемость и работоспособность видны только при запуске клиента. Локальный файловый URI может указывать на смонтированную файловую систему. Замена родительского пути или файла после проверки остаётся возможной. После передачи записи в очередь штатного редактора конфигурации отмена picker уже не управляет её завершением. Откат продуктового изменения — отмена коммита. Значение, которое пользователь сохранил в своём проекте, можно вернуть через настройки папки.

В checkout с установленными инструментами целевые тесты можно повторить следующими командами.

```sh
check_dir="$(mktemp -d)"
trap 'rm -rf "$check_dir"' EXIT
for suite in clangdExecutablePicker pythonInterpreterPicker; do
  pnpm exec esbuild "src/vs/workbench/contrib/myselfToolchain/test/browser/$suite.test.ts" \
    --bundle --platform=node --format=cjs --target=node24 --tsconfig=src/tsconfig.json \
    --outfile="$check_dir/$suite.cjs" || exit
done
pnpm exec mocha --ui=tdd "$check_dir"/*.cjs
```

Для нативной приёмки открыть тестовую доверенную локальную папку в отдельном профиле с проверенной версией клиента. Вызвать действие из Terminal и Files. Отмена и смена Workspace Trust до сохранения должны оставить файл настроек без изменений. Сохранение подтверждённого пути к локальному clangd должно изменить только `clangd.path` в этой папке и показать новое эффективное значение. При последующей инициализации проверить подсказки C и C++ и убедиться, что само сохранение не запустило новый процесс или сетевой запрос.
