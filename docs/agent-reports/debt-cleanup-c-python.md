# Техдолг, уборка и персональные C/Python

Задание: `debt-cleanup-c-python`. База: `origin/main` `adc50b65f0d`, ветка интегратора `maintenance/debt-cleanup`. Ответственный: тимлид; независимые проверки: агент аудита Git, агент тестового аудита и агент проверки языковых серверов. Шести рабочим чатам команды передано поручение сверить свой техдолг и старые артефакты.

Проблема: накопились завершённые ветки, старые сборки и невыгодный Rust-эксперимент; команда webview-тестов пропускала suite библиотеки. В персональном профиле владельца не было языковых клиентов C и Python. Ожидаемое поведение: убрать подтверждённые остатки без потери полезных изменений, запускать обе browser suite на свежем output, обеспечить подсветку, диагностику и completion C/Python.

Область: очистка Git refs и подтверждённых артефактов; команды тестирования документов и документация; отдельная пользовательская установка языковых клиентов. Корневые зависимости, runtime приложения и релизная упаковка не изменялись. Сборка приложения для этих изменений не требуется.

## Уборка

- Обновлён только `origin`, локальный main приведён fast-forward к актуальной базе. `upstream` не использовался.
- Неопубликованная ветка Rust-эксперимента и её код, cases, native binaries, targets и отчёт удалены. Отдельная установка rust-anything 2.0.0, навык и MCP-регистрация тоже удалены; пользовательский Rust toolchain и rust-analyzer сохранены. Настройки остальных MCP не изменены.
- Удалены 87 слитых локальных refs, затем ещё три refs архивированных merged worktrees и две промежуточные LSP-ветки, полностью входящие в сохранённую `agent/lsp-stdio-fixture`. Вместе с веткой Rust — 93 удалённых локальных refs на момент отчёта.
- Удалены 36 уже слитых remote branches. Перед удалением сверены SHA с origin, удаление выполнено атомарно с SHA leases. Коммиты остаются достижимыми из main. Публичная история и релизные теги не переписывались.
- Удалены пять устаревших сборок приложения, пустые остатки каталогов, пять дублирующих untracked отчётов и подтверждённые владельцами завершённые scratch-проверки. Дубли отчётов перед удалением побайтно сопоставлены с сохранёнными ветками.
- Владелец трёх дополнительных merged worktrees выполнил их штатное архивирование; каталоги исчезли и из git worktree list. Неиспользуемые native-бинарники, сборки и временные установочные файлы эксперимента не оставлены в checkout.
- Полезные уникальные LSP, QA/CI, release, отложенные GitHub и design-ветки сохранены. Содержательные проверки SHA/UTF-8/лимитов/traversal, native undo/redo и stdio fixture не удалялись.

Уборка managed worktrees выполнена частично: штатный инструмент Codex отказывает для пяти чистых merged каталогов с сообщением `Another active task still uses this worktree`. Повторная проверка прежним владельцем docs-right также получила `This worktree is owned by another task`. Защита не обходилась shell-удалением. Активный primary checkout остаётся рабочим каталогом техдолга, без Rust-эксперимента. Поэтому полное освобождение всех старых рабочих каталогов не заявляется.

## Код, тесты и документация

Принят и независимо просмотрен `11d0f0db321`: `test-webview` один раз компилирует расширение и исполняет `webview.test.cts` и `library-webview.test.cts`. Холодный прогон после удаления только generated out — 19/19 passed, 0 skipped. Полный `test` и его восемь файлов сохранены. Независимая проверка интегратора подтвердила неизменность полного test script и наличие одной compile с обеими suite. Успешные тесты без изменения проверяемого кода повторно не запускались.

README актуализирован по реально опубликованному v0.0.12-preview и его asset URLs. Исправлены устаревшие инструкции Open VSX вместо локального VSIX, статус локальной библиотеки, импорта папок и Markdown. Документация расширения больше не отрицает реализованный импорт папки. `git diff --check` прошёл; документационные изменения не требуют нового бинарного релиза.

Оставшийся подтверждённый долг: фиксированные/недостаточно точные ожидания в browser helpers, неинтегрированные проверки QA/CI и устаревший черновик project-post. Падение ожиданий в этой работе не воспроизводилось; тесты по возрасту или предположению не удалялись. Для CI сначала нужен review двух уникальных коммитов и доступности runners, для ожиданий — воспроизводимое падение и проверка конкретного render-state.

## C и Python: локальная установка

Фактический профиль определён по открытым файлам процесса установленной IDE. Старый изолированный smoke-профиль не принят за основной. Другие настройки сохранены, готовое приложение не заменялось.

- Python 3.14.3 уже установлен. Отдельный Python и виртуальное окружение не создавались. Программа со стандартной библиотекой успешно запущена системным `python3` без установки пакетов.
- Apple Clang и clangd 21.0.0 уже установлены. Настоящая C-программа собрана с `-std=c17 -Wall -Wextra -Werror` и запущена. Системный `gcc` на этом Mac также сообщает Apple Clang.
- Из локальных VSIX установлены `llvm-vs-code-extensions.vscode-clangd` 0.6.0, `detachhead.basedpyright` 1.40.2 и syntax-only `vscode.python` 1.95.3. Существующий syntax-only `vscode.cpp` сохранён. SHA-256 скачанных VSIX сверены с Open VSX; зависимости npm/pip для LSP не устанавливались.
- clangd настроен на системный бинарник, проверки загрузок/обновлений выключены, shell-script launcher не включён. BasedPyright использует bundled server и существующий Python, режим standard/openFilesOnly. Проектный language-server executable автоматически не выбирается. Workspace Trust и ограничения недоверенных проектов сохранены.
- CLI установленной IDE подтвердил наличие всех трёх новых расширений в фактическом пользовательском extensions-dir.

Независимый настоящий LSP stdio smoke прошёл для обоих серверов: initialize и completion/textSync capabilities; ошибочный didOpen дал одну error diagnostic; исправляющий didChange убрал диагностики; completion вернул поле структуры C и math.sqrt в Python; shutdown/exit завершились кодом 0. Использованы только сгенерированные временные файлы, серверы и тестовый каталог убраны. Отображение подчёркиваний в GUI и другие платформы этим headless smoke не проверялись.

Персональные расширения и настройки не входят в публичную поставку. Для stdlib-скриптов Python venv не обязателен; для проектов с разными сторонними зависимостями его следует выбирать отдельно. Текущего Clang достаточно для сборки C; установка второго компилятора не требовалась.
