## Решения и проверенные основания

- Созданы два дополнительных пользовательских чата разработчиков в существующем проекте. Начальные задания переданы; архитектор, безопасник, QA и продукт подключены к первой волне.
- Локальные шаблоны проектов исключены решением владельца. Другие 27 направлений приняты как постепенная очередь, а не одновременный релиз.
- Исходная база содержит обязательные `99373603913` и `01293638a16`: оба ancestry checks завершились exit 0. На старте рабочее дерево чистое.
- Первые рекомендации архитектора: существующие services, внутренние модели contribution, без нового общего DI/API; отдельно installed/enabled/activation/LSP unknown и per-root marker observations.
- Первые ограничения безопасника: не активировать расширения ради диагностики; до FileService не обращаться к remote/custom provider; не считать symlink проверенным файлом; не исполнять интерпретатор из конфигурации. Они переданы разработчикам.
- Попытка только чтения списка процессов не нашла запущенного установленного Nerded Code. Это не замер RAM и не baseline. Приложение ради измерения не запускалось, пользовательские окна и настройки не менялись.
- Существующие process explorer/diagnostics и sandbox process memory API изучены как точки переиспользования. Новая телеметрия, сборщик и Rust-бинарник не добавлены.
- Архитектор и безопасник передали source-review по базе `445e1988539` в чате. Уточнения внесены в roadmap и переданы разработчикам: строго local profile-aware inventory, запрет provider lazy-activation в будущем collector, статические Tasks wrappers после trust initialization/guard. Это ревью проекта решения, не sign-off ещё неготовой реализации.
- Проверен риск прямого `getInstalled`: `scanUserExtensions` может инициализировать отсутствующий реестр профиля, а `scanProfileExtensions` мигрирует старый формат. Диагностика может использовать уже подготовленный локальный список рабочего окна после штатной инициализации. Она должна подписывать отсутствие как «нет в локальном списке» и не запускать дополнительную загрузку. Прямой вызов сканера заменять чтением кэша только при подтверждении условий актуальности профиля.

## Первый замер импорта документации

В изолированном временном каталоге собран исходный `libraryImport.ts` с `esbuild`. На macOS ARM64 использован Node 26.8.2, свежий процесс на каждый запуск, пять повторов в перемешанном порядке для каждой нагрузки. Фикстура состоит из синтетического UTF-8 текста с кириллицей и emoji. `process.memoryUsage().arrayBuffers` измерен до вызова и при удерживаемом результате, пик физического footprint получен из `/usr/bin/time -l`.

| Размер входа | Медиана пикового footprint | Диапазон footprint | Прирост ArrayBuffer при возврате |
| --- | ---: | ---: | ---: |
| Пустая папка | 13,5 МиБ | 13,5–13,7 МиБ | 0 МиБ |
| Один файл, 16 МиБ | 65,2 МиБ | 65,1–65,3 МиБ | 31,9 МиБ |
| Четыре файла, 63,9 МиБ | 153,4 МиБ | 149,8–153,6 МиБ | 95,8 МиБ |

Тест охватывает чтение и проверку UTF-8 до записи в хранилище расширения. Это отдельный процесс Node без Electron, других расширений и LSP. Замер подтверждает значительный пик в этой операции и даёт базу для сравнения с обработкой по одному документу. Выигрыш от Rust и вклад импорта в повседневную память IDE остаются неизмеренными. Временные данные удалены.

Второй прогон добавил последовательную запись тех же четырёх файлов в локальный временный каталог через Node. Сравнили исходник, чтение без второй копии Buffer и временный вариант, который сразу записывает полученный документ и сохраняет только его имя. По семь свежих процессов на вариант. Проверка SHA-256 всех выходных файлов прошла в каждом прогоне.

| Вариант | Медиана пикового footprint | Диапазон footprint | Медиана чтения и записи |
| --- | ---: | ---: | ---: |
| Исходник | 153,9 МиБ | 153,8–154,0 МиБ | 150,8 мс |
| Одна копия байтов на файл | 137,6 МиБ | 137,5–141,3 МиБ | 149,6 мс |
| Одна копия и запись по мере чтения | 121,8 МиБ | 121,6–141,7 МиБ | 127,7 мс |

Медиана второго варианта ниже на 16,3 МиБ, третьего на 32,1 МиБ (21%). У третьего сильнее разброс. Оба кандидата остаются TypeScript. Этот замер проверяет идею на синтетических данных. Он не моделирует файловый IPC VS Code, commit метаданных, отмену или rollback. Для продуктовой реализации нужны ограниченное промежуточное хранилище и проверка поведения при прерывании. Прототипы и временные файлы удалены, продуктовый импорт не менялся.
