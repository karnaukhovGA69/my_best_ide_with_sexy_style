# diagnostic-log-native-acceptance

Статус: ГОТОВО. Владелец: интегратор. База: main 8e389a13efb; проверяется frozen binary 3dbf0296716.

Область: этот отчёт, временный native QA fixture вне репозитория. Проверить существующий desktop LogsDataCleaner в изолированном профиле: удаление старого архива при превышении 100 MiB, сохранение недавнего сеанса и постороннего каталога. Пользовательские профили/логи не трогать. Runtime, публикация и app installation не входят в scope; build не нужен.

Native acceptance прошла на окончательном signed app source 3dbf0296716432e7d6e3d61196a71865ccb7ad7c. Изолированы user-data/extensions/shared storage и workspace. Архив с вложенным sparse-файлом 101 MiB и mtime два дня назад удалён штатным shared-process cleaner после старта: возраст меньше 7 дней и число архивов меньше 9, следовательно сработал общий бюджет размера. Недавний архив, текущий log session и посторонний каталог с файлом сохранены. Процесс проверки завершён; пользовательские данные не изменялись.

Результат добавлен в preview QA JSON как diagnosticLogRetention; подписанный app, ZIP и их checksum не менялись. Проверка подтверждает существующую startup archive policy, не жёсткую квоту живых логов и не атомарную защиту от произвольного внешнего писателя. Фикстура и лог проверки остались локальными, персональные пути в отчёт не включены. Build не выполнялся.
