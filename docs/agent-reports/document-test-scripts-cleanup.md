# Очистка команд тестирования документов

Задача `document-test-scripts-cleanup`, база `adc50b65f0d`, ветка `agent/document-test-scripts-cleanup`. Ответственный — агент тестового аудита; независимый проверяющий — интегратор.

Проблема: `test-webview` исполнял только тесты редактора из существующего `out`, пропуская browser suite библиотеки. README предлагал отдельную компиляцию перед `test`, который сам уже выполняет `compile`.

Область изменений: `extensions/myself-documents/package.json`, `README.md` и этот отчёт. `test-webview` теперь один раз выполняет `compile` и запускает обе browser suite. Полный `test` и его glob сохранены. README содержит отдельные команды для полного и узкого запуска без повторной компиляции. Продуктовый код, зависимости, тестовые сценарии и fixed waits не менялись.

Критерии приёмки выполнены: обе browser suite реально прошли после удаления только игнорируемого сгенерированного `out`; в логе запуска один шаг `compile`; полный тестовый glob сохраняет прежний состав.

## Проверки

На macOS ARM64, Node 26.8.2, pnpm 12.16.0 выполнен холодный `pnpm --dir extensions/myself-documents run test-webview`: компиляция host и webview, затем обе browser suite — 19/19 passed, 0 skipped. Версия pnpm запущена через `pnpm dlx pnpm@12.16.0`; использованы существующие локальные зависимости рабочего каталога, установка зависимостей всего репозитория не выполнялась. В логе pnpm 12 показан один шаг `pnpm -C ../.. exec tsc ... && ... && node esbuild.webview.mts`. Внешняя вспомогательная проверка сначала ожидала прежний формат логов pnpm и ошиблась при подсчёте; сами компиляция и тестовая команда завершились успешно.

Скрипт полного `test` сравнен с базой и не изменён: `pnpm run compile && node --test test/*.test.cts`, тот же набор восьми файлов. Полный набор повторно не запускался, поскольку проверки и продуктовый код не менялись. `git diff --check` прошёл. Полная сборка приложения, native smoke, Windows и Linux не выполнялись; для изменения команд тестирования они не требовались.

Для независимой проверки интегратору достаточно просмотреть две строки script/README и результаты целевого прогона. Fixed waits остались отдельной задачей: воспроизводимое падение в этой работе не получено.
