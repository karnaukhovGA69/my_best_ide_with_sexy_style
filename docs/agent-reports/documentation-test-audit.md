# Ревизия тестов каталога и импорта документации

Готово к независимому ревью. База `8c5155c82de`, ветка `agent/documentation-test-audit`. [Задача #12](https://github.com/karnaukhovGA69/my_best_ide_with_sexy_style/issues/12)

- В `library.test.cts` тест снимка кэширует имена по директории и проверяет точный регистр каждого компонента пути. Раньше на 4306 статей приходилось столько же чтений списков файлов. Теперь на текущем каталоге шесть чтений для корня и пяти подкаталогов. Проверки SHA-256, UTF-8, размера, лицензий и ссылок на одноимённые Linux manpages сохранены. Проверка отклонения каталога использует заведомо корректный исходный пример, отличает повтор ID от повторения пути и действительно проверяет неподдерживаемый формат PDF, заявленный в имени теста.
- В `library-import.test.cts` сначала проверяется успешный импорт файла с многобайтным текстом ровно на допустимой границе. Затем каждый лимит снижается отдельно. Проверяются ожидаемые ошибки лимитов, отмены и код ошибки декодера. Для проверки UTF-8 тот же файл заменяется некорректными байтами той же длины, поэтому срабатывание лимита не может выдать ложный успех. Проверки симлинков и ссылок между коллекциями сохранены.

На macOS ARM64, Node 26.8.2 и pnpm 11.25.0, `node --test extensions/myself-documents/test/{library,library-import}.test.cts` прошёл до и после правок, 7/7. В этих прогонах время теста целостности составило 11,15 с до правок и 0,94 с после. Это замер локального прогона, порога времени в тесте нет. Полная проверка расширения `pnpm --dir extensions/myself-documents test` прошла до и после правок, 49/49. `git diff --check` прошёл.

В отдельной временной копии скомпилированного импортера по одному отключил проверку числа документов, числа записей, общего числа байт и строгий UTF-8. Во всех четырёх случаях усиленный тест упал на ожидаемой проверке. На временной файловой фикстуре с `GO/index.html` в каталоге и `go/index.html` на диске проверка точного регистра упала на компоненте `GO`, хотя файловая система разрешила путь. Тестовые варианты и фикстуры не входят в коммит.

Продуктовый код, CI и сборка приложения вне области изменений. Перед слиянием интегратор проверяет этот diff на актуальной базе. Если #9 перенесёт официальный каталог, его тест целостности должен переехать вместе с данными.
