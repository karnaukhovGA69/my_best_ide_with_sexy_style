# Размеры установленных расширений

Задача `extension-resource-diagnostics`, направление №21. Ветка `codex/extension-resource-diagnostics`, база `7f3a643fe9d`. Область правок ограничена `src/vs/workbench/contrib/myselfExtensionResources/**` и этим отчётом.

- **Help → Check Extension Sizes** показывает размер каждого локального расширения в списке активного профиля, включая отключённые. Встроенные расширения подписаны отдельно. Нулевой, отсутствующий и недопустимый размер отображается как **Unknown**. Учитывается одна запись на регистронезависимый ID. Диалог прокручивается и выводит строки текстом. Следующее открытие читает актуальное состояние кэша, в том числе после удаления.
- Источник размера — `ILocalExtension.size` в `IExtensionsWorkbenchService.installed`. При установке `extensionManagementService.ts` сохраняет результат `computeSize` в метаданных расширения, поэтому число отражает логический объём по этим метаданным на момент их расчёта. Диалог не вычисляет освобождаемые блоки диска, не суммирует версии или профили и не проверяет последующие изменения файлов.
- Открытие использует только кэш уже работающего сервиса расширений. Нет повторного `queryLocal`/`getInstalled`, вызова менеджера расширений, сетевой операции, запуска процессов, сканирования каталога или записи состояния. Отсекаются удалённые окна, ресурсы с нелокальной схемой или authority и расширения, привязанные к workspace. Локальная схема сама по себе не определяет физический тип монтирования.
- Для профиля используется общая ранняя подписка **Check My Installation**, без повторной подписки на сброс списка. Смена профиля во время ожидания и неподтверждённое состояние кэша приводят к сообщению о недоступности. Это наблюдение существующего кэша, а не независимая проверка всех файлов выбранного профиля.
- Диалог объясняет, что расширения могут делить хост и индивидуальное потребление RAM неизвестно. **Help → Open Process Explorer** показывает потребление процессов. Диагностика размеров сама его не открывает.

## Проверки и подключение

- Выполнены 5 тестов чтения кэша в отдельном временном esbuild-бандле под `node --test` на macOS ARM64, Node 26.8.2. Проверены сохранённые, нулевые, отсутствующие и недопустимые размеры, регистронезависимые дубли, фильтрация remote/authority/workspace, безопасные подписи, смена профиля при отложенной инициализации, ошибки, удаление записи и пустой список.
- Целевая проверка TypeScript 6.0.3 через Compiler API с опциями `src/tsconfig.json` прошла для трёх файлов. Целевой ESLint завершился без ошибок с четырьмя предупреждениями о регистрации каталога в `code-import-patterns` и локализации. Производственная сборка и нативный диалог остаются на приёмке общего пакета.

Интегратору добавить в `src/vs/workbench/workbench.desktop.main.ts` импорт `./contrib/myselfExtensionResources/browser/extensionResourceDiagnostics.contribution.js` после импорта `installationDiagnostics.contribution.js`, а в `build/lib/i18n.resources.json` зарегистрировать `vs/workbench/contrib/myselfExtensionResources` в `vscode-workbench`. Нового API, зависимости, настройки или миграции данных нет.

Нативная приёмка: в локальном окне сравнить результаты с Extensions для установленного вручную расширения известного размера и встроенного без метаданных, отключить и удалить ручное расширение, повторно открыть диалог. Проверить переключение профиля и прокрутку в узком окне. При наличии удалённого окна проверить отсутствие команды. Открытие диагностики само по себе не должно инициировать запуск хоста, чтение каталогов расширений или HTTP-запрос.
