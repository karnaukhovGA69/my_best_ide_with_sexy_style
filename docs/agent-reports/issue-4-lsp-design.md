# Подключение скачанного языкового сервера без пересборки

Задача [#4](https://github.com/karnaukhovGA69/my_best_ide_with_sexy_style/issues/4). Предложение для ревью, база `8c5155c82de`.

## Выбор подхода

Поставить один универсальный LSP-клиент как отдельное настольное расширение VSIX. После установки расширения пользователь указывает скачанный исполняемый файл, аргументы и типы файлов. Клиент работает в настольном extension host, запускает сервер отдельным процессом и подключает его функции к редактору. Добавление, замена и переключение серверов происходят во время работы. Обновления самого клиента тоже распространяются как VSIX. [Модель расширения с языковым сервером](https://code.visualstudio.com/api/language-extensions/language-server-extension-guide).

| Способ | Где подходит |
| --- | --- |
| Существующий VSIX от разработчика языка | Уже работает через ручную установку. Даёт специфические возможности вроде загрузки решений, запуска тестов и интеграции с отладчиком, если их поддерживает расширение. Совместимость зависит от API редактора, платформы, зависимостей и условий распространения пакета. |
| Универсальный клиент как VSIX | Нужен для скачанного сервера без собственного расширения. Позволяет добавить произвольный профиль без списка разрешённых языков и без изменения приложения. |
| LSP-клиент в ядре редактора | Может дать встроенный интерфейс сразу после установки IDE. Потребует поставлять и обновлять клиент вместе с приложением. Для первой версии достаточно отдельного VSIX. |

В текущем форке есть ручная установка через Extensions → Install from VSIX и CLI `--install-extension <file.vsix>` ([CLI](../../src/vs/platform/environment/node/argv.ts), [обработка](../../src/vs/code/node/cliProcessMain.ts)). Для протокола взять `vscode-languageclient/node` версии 10.1.1, которая уже используется в [JSON-расширении](../../extensions/json-language-features/client/src/node/jsonClientMain.ts) и поддерживает API установленного редактора 1.146.0. Упаковать библиотеку внутрь VSIX. [API редактора](../../src/vscode-dts/vscode.d.ts) предоставляет диагностику, провайдеры подсказок и статус языка. Первая версия может жить в самостоятельном пакете с отдельным циклом сборки и проверкой VSIX в установленном приложении.

## Сценарий пользователя

1. Один раз установить VSIX клиента. Открыть раздел **Языковые серверы** в Explorer и выбрать **Добавить сервер**. Объявить представление через `contributes.views.explorer`, команду через `contributes.commands` и кнопку через `menus["view/title"]`. В качестве примера в форке есть [раздел npm Scripts](../../extensions/npm/package.json).
2. Выбрать скачанный файл или интерпретатор, например `dotnet`. Добавить аргументы отдельными значениями, выбрать язык или шаблон файлов и папку проекта. Для неизвестного редактору языка можно сопоставить файлы по glob, например `**/*.foo`, и явно задать отправляемый серверу `languageId`.
3. Нажать **Включить** для выбранной папки. Увидеть состояние, доступные функции и причину сбоя в панели. Действия **Остановить**, **Перезапустить**, **Изменить** и **Открыть журнал** работают из той же панели. При замене версии можно выбрать новый бинарник и перезапустить сервер.

Минимальный профиль хранит ID и имя, абсолютный путь, массив аргументов, правила выбора локальных документов, отправляемый `languageId` при необходимости, привязку к папке, `initializationOptions` и настройки для `workspace/configuration`. Для первого выпуска брать `cwd` и корень LSP из выбранной локальной папки. Переменные окружения и аргументы вводятся отдельно, без интерполяции из проекта и без запуска через shell. Исполняемые профили и активации хранятся в пользовательском состоянии расширения. Импорт шаблона, если его добавим, создаёт выключенный профиль для проверки пути и аргументов.

### Сопоставление файлов и папок

На каждую явно выбранную папку создать отдельную сессию с `clientOptions.workspaceFolder`. В версии 10.1.1 эта опция устанавливает `rootUri` и список из одной папки в `initialize`. Она сама по себе не сужает область провайдеров. Для этого нужен `documentSelector` с `scheme: "file"` и `RelativePattern` от корня. Вложенные корни распределяются по ближайшей назначенной папке. Для первой версии файлы вне открытых папок требуют открыть подходящую папку.

При наличии зарегистрированного языка использовать его ID в селекторе и стандартной синхронизации. Для неизвестного языка селектор может содержать только схему и шаблон, например `{ scheme: "file", pattern: new RelativePattern(folder, "**/*.foo") }`. В форке `languages.setTextDocumentLanguage` отклоняет незарегистрированные идентификаторы, а штатный конвертер отправляет текущий `TextDocument.languageId`, часто `plaintext` для неизвестного расширения. Если сервер ждёт `foo`, подменять поле `params.textDocument.languageId` только в исходящем `textDocument/didOpen`. Обёртка над `MessageWriter` в фабрике `ServerOptions` позволяет сделать это после конвертации. Так встроенная синхронизация сохраняет учёт открытых документов и события, по которым запускается pull-диагностика. Самостоятельная отправка `didOpen` из middleware в обход `next` может пропустить эти события. При изменении сопоставления перезапустить сессию, чтобы сервер заново получил открытые документы. [Проверка ID в форке](../../src/vs/workbench/api/browser/mainThreadLanguages.ts), [синхронизация клиента](https://github.com/microsoft/vscode-languageserver-node/blob/main/client/src/common/textSynchronization.ts), [API транспорта](https://github.com/microsoft/vscode-languageserver-node/blob/main/client/src/node/main.ts).

Сервер может зарегистрировать свой селектор во время сессии. В 10.1.1 он заменяет исходный селектор для конкретной возможности. Ограничивать динамические регистрации через `middleware.handleRegisterCapability`: согласовать протокольный ID с локальным селектором и отклонить неподдерживаемые регистрации за пределами выбранной папки. Проверять область и при отправке документов, и при выдаче подсказок и диагностик. Для push-диагностики использовать `middleware.handleDiagnostics`, для pull проверять селекторы и документы при выдаче результатов. Не связывать фильтр диагностики только с открытыми вкладками, поскольку сервер может сообщать и об ошибках в закрытых файлах того же проекта. [Регистрация возможностей и обработка диагностик](https://github.com/microsoft/vscode-languageserver-node/blob/main/client/src/common/client.ts).

При первом включении показать выбранный путь, аргументы и папку. Перед каждым запуском проверять Workspace Trust и пригодность файла для запуска. Изменение команды или места установки должно вернуть профиль в состояние проверки. Настройки из скачанного проекта не могут активировать процесс или подменять команду. У процесса есть доступ с правами пользователя, а инструменты, которые он запускает, например Cargo или MSBuild, могут исполнять код проекта. Применить [Workspace Trust](https://code.visualstudio.com/api/extension-guides/workspace-trust) и не объявлять его изоляцией процесса. Секреты подключения оставлять в предусмотренной сервером конфигурации или хранилище секретов. Не выводить полное окружение и содержимое протокола в обычный журнал.

## Протокол и границы поддержки

Первая версия поддерживает локальные серверы LSP поверх stdio и использует возможности, которые сервер объявляет при инициализации. Обязательная проверка клиента включает синхронизацию открытых документов, автодополнение с разрешением результата, push-диагностику и pull-диагностику. Для серверов без конкретной возможности состояние должно это показывать. Клиент должен использовать согласованный режим синхронизации и отдельно проверять pull-диагностику во время правок. У 10.1.1 параметры `diagnosticPullOptions.onChange` и `onSave` по умолчанию выключены. Установить режим обновления и проверить его с rust-analyzer. [Спецификация LSP 3.17](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/).

Следующий шаг при необходимости — профили для локального TCP и сокета, с явным выбором адреса и понятным владением процессом. Серверы с другим транспортом могут работать через совместимый stdio-адаптер или собственный VSIX. Частные сообщения, нестандартное обнаружение проектов и специфические команды требуют поддержки поставщика либо отдельного адаптера. Отдельно остаются TextMate-грамматики, отладка, тесты и выполнение SQL. Общий профиль описывает запуск и протокол, SDK и зависимости по-прежнему устанавливаются по инструкции сервера.

Обрабатывать ошибки пути, несовместимую архитектуру, отсутствующий SDK, таймаут инициализации и неожиданный выход. Хранить дескриптор процесса из фабрики транспорта и привязать его к одной сессии. На остановке вызвать `client.stop()` для `shutdown` и `exit`, затем дождаться фактического выхода. Если процесс завис на старте или не вышел по таймауту, закрыть каналы и завершить принадлежащий сессии процесс. Отдельно проверить демоны, которые запускаются дочерним процессом и могут пережить его. Завершать только процессы, запущенные для этой сессии, используя управляемую группу процессов или предусмотренное сервером завершение выделенного демона. Уже существующий общий демон останавливается отдельно его владельцем. Снимать подсказки и диагностику остановленной сессии. При закрытии окна или снятии привязки процесс должен завершаться. Сбой не должен запускать бесконечные перезапуски. Клиент сам ничего не скачивает и не настраивает каталоги.

| Сервер | Команда и параметры | Что проверить в редакторе |

| Rust | Путь к отдельному `rust-analyzer`, аргументы пустые, язык `rust`, корень Cargo. Установить совместимые Rust toolchain и `rust-src`. | Увидеть ошибку типов и подсказки методов `String`. Проверить обычный Cargo-проект и диагностику pull. [Установка rust-analyzer](https://rust-analyzer.github.io/book/installation.html). |
| F# | Исполняемый `fsautocomplete` или путь к `dotnet` с аргументом — путём к `fsautocomplete.dll`. | PostgreSQL | Путь к `postgres-language-server`, аргументы `lsp-proxy` и при необходимости `--config-path=…`, язык `sql`. | Без базы увидеть ошибку синтаксиса. На отдельной тестовой базе проверить подсказки таблиц и типов после подключения и настройки схемы. [Конфигурация PostgreSQL LSP](https://pg-language-server.com/latest/configuration/). |

Пользователи, у которых уже установлен Go, rust-analyzer, Ionide или Postgres Language Server VSIX, могут продолжать пользоваться им. При переходе на общий клиент отключить пересекающийся анализ для выбранного языка и папки, чтобы подсказки и ошибки не дублировались. Автоматическое отключение чужих расширений и перенос их настроек не входят в первый выпуск.

## Проверено для этого анализа

Временный клиент отправил JSON-RPC по stdio четырём уже установленным серверам в отдельных временных папках. Все четыре ответили на `initialize` и объявили completion. Go, Rust и F# прошли `initialized → shutdown → exit` с кодом 0. PostgreSQL 0.28.2 через `lsp-proxy` ответил на `shutdown`, но процесс не завершился за 5 секунд даже после EOF на stdin, поэтому его принудительно остановили. После завершения прокси остался процесс `__run_server`, запущенный для временного проекта. Его остановили отдельно. При интеграции проверить завершение и прокси, и созданного им демона. PostgreSQL проверялся без подключения к базе. Кроме пробы транспорта сверены манифесты форка и код опубликованного пакета `vscode-languageclient@10.1.1`. Работу переопределения ID и отображение диагностик и подсказок через будущий VSIX ещё предстоит проверить в редакторе.

## Критерии реализации

- Установить клиент VSIX в уже собранный Nerded Code. Через интерфейс подключить скачанный сервер, поменять бинарник и снова получить подсказки без сборки приложения и расширения.
- Подключить один дополнительный LSP-сервер по той же форме без изменений исходников клиента. Проверить два корня и сервер с незнакомым расширением файла, который принимает только ожидаемый `languageId` и динамически регистрирует подсказки. Смена или выключение профиля должна снять старые провайдеры и диагностику.
- Проверить стандартные сценарии из таблицы и отсутствие дублей при использовании одного клиента на язык и папку. Использовать тестовый LSP-сервер для сценариев неверных ответов, таймаута, остановки и перезапуска.
- Проверить, что недоверенная папка и её настройки не запускают процесс, а выключение профиля удаляет его диагностику и завершает принадлежащие ему процессы.
