# Локальное хранилище PDF в нативном редакторе

Ветка `codex/library-pdf-native-storage`, база `ece22894e40d9e63342d5f9709dbb423032c0996`, код `15495133c79d4ea800f59054c89feb0c7f6d1716`. Изменены только обработчики PDF библиотеки `myself-documents` и их тест. Готово к повторной нативной проверке.

В desktop-сборке локальный хост расширений получает каталог профиля с URI `vscode-userdata`. Это псевдоним локального пути `appSettingsHome`. Старый PDF-обработчик допускал только схему `file` и отказывал в открытии сохранённой копии. Для импорта, открытия и удаления добавлено общее разрешение пути из собственного `context.globalStorageUri`. Обе локальные схемы разрешаются только в desktop UI и локальном хосте расширений. `context.extension.extensionKind` различает локальный и удалённый хост. `env.remoteName` относится ко всему окну, поэтому не используется для различения процессов.

Пустые authority, query и fragment и допустимый абсолютный путь проверяются до чтения или записи. URI выбора исходного PDF сохраняет схему `file`. При недоступном хранилище удаление отказывается до обновления записи библиотеки. Проверки UUID, размера, SHA-256, дескриптора и безопасного удаления сохранённой копии используют неизменённую реализацию. Текстовые импорты и поиск вне задачи.

На macOS ARM64 под запретом сети прошли 77 тестов библиотеки и PDF. С теми же новыми тестами на прежнем коде было 75 успешных и два падения. Фикстура зарегистрированных команд подтверждает импорт, открытие проверенных байтов через совместимый viewer и удаление копии с `vscode-userdata`. Отдельно проверены отказ удалённому хосту, Web UI, custom/remote URI, сетевому и неоднозначному пути, query и fragment, отсутствие побочных чтений или обновления записи. Целевые TypeScript, ESLint и `git diff --cached --check` прошли. Тесты использовали отдельный временный каталог. Подписанный артефакт, пользовательские профили и окна не изменялись. Интегратор повторяет проверку фактического desktop-хоста на собранном артефакте.
