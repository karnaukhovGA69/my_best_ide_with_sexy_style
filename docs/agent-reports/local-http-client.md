# Локальный HTTP-клиент для loopback API

Задача `local-http-client` (№23), база `74d67dda260` с `d8c6bacc3b3` в истории, ветка `codex/local-http-client`, код и тесты `ad527fa326d3ed372b3cc6016975b7f28589c8df`. Изменения ограничены новым `extensions/myself-http-client/**` и этим отчётом. Готово к независимой проверке и отдельной упаковке.

Команда **Send Local HTTP Request…** доступна в заголовке текстового редактора и в меню Files. Пользователь вручную выбирает GET или POST и вводит URL. POST принимает одну строку UTF-8 с фиксированным типом `text/plain`. Модальное подтверждение показывает выбранный метод, нормализованный loopback origin и точный путь, который получит сервер. Query остаётся в полях действия и текущем запросе, в подтверждении отмечено только его наличие. Длина тела видна до передачи. Аргументы команды игнорируются. Доверие и локальность окна проверяются до приглашений, после ожидания пользовательских действий и непосредственно перед сетевым вызовом.

Валидатор проверяет исходный authority до стандартной нормализации URL и принимает только литералы `127.0.0.1` или `[::1]` в HTTP(S), без учётных данных и фрагмента. Node получает фиксированный IP, порт и путь. Используется один сокет на запрос со своим агентом без ambient proxy, отклоняются upgrades, редирект остаётся ответом. HTTPS явно включает проверку сертификата. Данные берутся из ручного ввода, без чтения файлов, конфигурации проекта, переменных окружения, пользовательских заголовков или cookies. Истории и сохранённых запросов нет.

Лимиты: 2048 символов URL до и после нормализации, 16 КиБ UTF-8 тела, 8 КиБ заголовков ответа, 64 КиБ тела ответа и 10 секунд на запрос. При превышении лимита тела ответа панель показывает статус и метку ограничения вместе с началом текста. Отмена закрывает клиентское соединение. Уже принятый сервером POST может завершиться независимо от отмены. Ответ декодируется как UTF-8 и показывается экранированным текстом в одной Webview без скриптов, command URI или resource roots. CSP разрешает только фиксированный встроенный CSS с nonce. Панель хранит видимый ответ в памяти до замены или закрытия.

Проверки:

- Целевой TypeScript emit из `extensions/myself-http-client/tsconfig.json` во временный каталог, ESLint семи TypeScript-файлов и `git diff --check` прошли. Node 26.8.2 выполнил 11 из 11 тестов. Подставные API проверили отказ до чтения ввода в Restricted Mode и удалённом окне, выход без отправки при отказе и потере доверия, модальный обзор точного пути, один вызов после подтверждения, местную валидацию, фиксированные транспортные параметры, ограниченный ответ и отмену с закрытием обоих потоков.
- Отдельный прогон с временными серверами только на собственном loopback подтвердил GET, UTF-8 POST, возврат 302 без повторного запроса, закрытие клиентского соединения после отмены и отказ недоверенному TLS-сертификату. При активной конфигурации прокси глобального агента тестовый прокси не получил запросов. Все временные серверы, сертификаты и выходные файлы удалены.
- Настоящий `ContextKeyExpr` проверил оба меню для доверенного, ограниченного и удалённого окон. Временный standalone VSIX собран из скомпилированных файлов и содержал 10 файлов пакета и два файла метаданных VSIX. Тесты, исходники, зависимости и пути worktree отсутствовали. Архив удалён. `isDistributionExtension('myself-http-client')` вернула false.
- Нативная проверка меню, модального диалога и отмены на рабочем профиле остаётся в общем desktop-прогоне. Прямые внешние HTTP-сервисы принадлежат отдельному будущему срезу.

Интеграция: включить исходный коммит, оставить модуль вне встроенной поставки и собрать отдельный VSIX по командам в `extensions/myself-http-client/README.md`. Пользователь устанавливает выбранный файл через **Extensions → Install from VSIX…**. Общие registration, package/lockfiles и процессы приложения менять для этого среза не требуется.
