# Открытие библиотечного PDF в локальном просмотрщике

Задача `local-pdf-library-viewer-bridge`, направление №15. База `b4ca2d593d1`, ветка `codex/local-pdf-library-viewer-bridge`. Проверенный код `7dafe942dd1d0024162b42cf539e45c450b7fd61`. Область правок ограничена библиотекой `extensions/myself-documents`, её тестами и этим отчётом.

- Пользователь открывает зарегистрированный PDF из дерева библиотеки или выбирает его в поиске по названиям. Штатная команда принимает ID записи. Путь, URI, объект записи и добавочные аргументы не определяют файл. Внутренняя навигация текстового reader по ссылкам, истории и результатам полнотекстового поиска PDF не открывает. Штатная команда доступна программным клиентам IDE и может открыть уже зарегистрированный ID.
- Из текущей записи берутся UUID и сохранённый SHA-256. Файл определяется только как `pdf-imports/<UUID>.pdf` под локальным хранилищем расширения. Чтение ограничено 16 MiB и использует ту же проверку снимка, что и удаление. Путь каталога канонический, символическая и жёсткая ссылки отклоняются, проверяются inode, итоговые байты и заголовок PDF. Исходный файл импорта не читается при открытии. При пропаже или изменении копии пользователь получает предложение импортировать её снова.
- Библиотека обращается к `myself.myself-local-pdf-viewer` версии `0.1.0` из своего extension host. Требуются `ExtensionKind.UI`, локальный file URI без authority, query и fragment и API `{ apiVersion: 1, openBytes(bytes: Uint8Array): Promise<boolean> }`. Установленный активный просмотрщик с несовместимым API отклоняется до чтения. Активация допустима после проверки копии. В API передаётся ровно один аргумент с проверенными байтами, без имени, пути и URI.
- Перед активацией и передачей байтов проверяются поколение навигации, список расширений, регистрация документа и состояние библиотеки. После активации вновь проверяются идентичность API и актуальность операции. Подтверждённое удаление инвалидирует ранее начатое открытие и закрывает новое открытие той же записи до завершения операции сохранения.
- При отсутствии совместимого локального просмотра показано, как установить его вручную через **Extensions → Install from VSIX…**. Отказ просмотрщика получает отдельное сообщение. Автоустановки, открытия внешнего приложения и перехода в текстовый reader нет.

## Проверки

Изолированная компиляция host-расширения TypeScript 6.0.3, целевой ESLint и 84 из 84 тестов прошли на macOS ARM64 с Node 26.8.2. Четыре библиотечных набора запущены под системным запретом сети на синтетических байтах. Тесты проверяют ровно один байтовый аргумент, чтение только UUID-копии, игнорирование путей и чужих объектов, отклонение другого ID, версии, хоста и API, блокировку чтения содержимого ссылок и отсутствие активации при испорченной копии. Отдельно проверены навигация, подмена API, подтверждённое удаление и disposal во время ожидания, отказ просмотрщика, рабочее удаление и прежние Markdown-записи.

Для проверки из корня репозитория с установленными зависимостями:

```sh
pnpm exec tsc -p extensions/myself-documents/tsconfig.json
/usr/bin/sandbox-exec -p '(version 1)(allow default)(deny network*)' "$(command -v node)" --experimental-strip-types --test \
  extensions/myself-documents/test/library-host.test.cts \
  extensions/myself-documents/test/library-pdf.test.cts \
  extensions/myself-documents/test/library.test.cts \
  extensions/myself-documents/test/library-import.test.cts
```

Граница проверки — библиотечный host до вызова `openBytes` на подставном расширении. Для интеграции нужен точный проверенный VSIX 0.1.0, который действительно экспортирует v1, и отдельная приёмка renderer, локальных ресурсов и сценария в окне IDE. Полная сборка, GUI и пользовательские документы в этой работе не использовались.
