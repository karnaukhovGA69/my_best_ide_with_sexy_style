# Опциональный локальный просмотр PDF

Задание №15 `local-pdf-viewer`, ветка `codex/local-pdf-viewer`. База локального main — `698f681a9e2322b27f3e01ad8a14f988a263a79d` с исправлением привязки зарегистрированной PDF-копии `7be1095d33f`. TypeScript-кандидат — `fbb112d768dcb012c81dbc1785a0b00749989446`. API для библиотеки реализован отдельным коммитом `8574f9f2b82d4e1e6ce0b436a6e51327a1f89a5c` поверх `7648502814b`. Пакет с этим API готов к независимой приёмке. Изменения в `extensions/myself-local-pdf-viewer/` готовы к независимой приёмке исходников и VSIX.

## Пакет для приёмки

- `myself.myself-local-pdf-viewer` 0.1.0, движок Code `^1.146.0`, локальный UI extension host, без runtime-зависимостей. VSIX находится в игнорируемом `extensions/myself-local-pdf-viewer/dist/myself-local-pdf-viewer-0.1.0-api-v1.vsix` и содержит 15 файлов. Размер 533 398 байта. SHA-256 — `0676209f5504a74473fd90ea2db4fa5d9c6bac18017e57dfb29c0e48bbd2dd62`. Пакет собран для ручной установки после приёмки.
- После установки действие «Открыть локальный PDF…» в меню вида Files вызывает системный выбор одного файла. Команда `myself.localPdfViewer.open` игнорирует переданные аргументы. Просмотр открывается рядом с редактором. Чтение начинается после выбора обычного локального файла с заголовком PDF и размером до 16 МиБ. У URI запрещены authority, удалённая схема и UNC-путь. Дескриптор и метаданные сравниваются до и после ограниченного чтения. ОС может обслуживать локальный путь через смонтированную файловую систему.
- Поддерживается до 200 страниц, одна страница за действие и один worker за раз. Веб-интерфейс сообщает об отсутствующих ресурсах, превышении лимитов, таймауте, защищённом паролем документе или неподдерживаемом рендере. Отрисовка ограничена 2048 пикселями на грань и 2 млн пикселей на выдачу. Суммарный учёт поверхностей фабрики ограничен 8 млн пикселей. Дедлайн страницы — 5 секунд. Эти пределы не задают жёсткую квоту памяти декомпрессии, движка или Chromium.
- В VSIX входят один canvas-worker, оболочка, локализации EN/RU, MIT и Apache‑2.0 лицензии. Встроенные действия PDF остаются пассивными. Адаптер не подключает stock viewer, scripting manager, sandbox PDF.js, вызовы печати, ссылки, слой аннотаций, формы, XFA, системные шрифты, внешние ресурсы или WASM. Канал оболочки — отдельный `MessagePort`, два модуля движка общаются через второй `MessageChannel` внутри worker. Вход worker — локальные байты и номер страницы, выход — проверяемый RGBA или фиксированный код ошибки. Локальные корни webview пусты. CSP разрешает только nonce-скрипт, nonce-стиль и Blob-worker. `connect-src 'none'` наследуется Blob-worker. Отмена закрывает канал и завершает worker, закрытие webview отзывает Blob URL.

## Происхождение и воспроизводимость

Официальный [релиз Mozilla PDF.js v6.5.438](https://github.com/mozilla/pdf.js/releases/tag/v6.5.438) привязан к `0a4153349dc473ba950fc17941c5ca7eda43c1de`. SHA-256 архива `fcbe9ba21d9911843e3502adc178a7f549a524a4055f887bedc942e5490c6ba1` совпал с `digest` в [GitHub Release API](https://api.github.com/repos/mozilla/pdf.js/releases/tags/v6.5.438). Лицензия в архиве побайтово совпала с [лицензией исходного коммита](https://github.com/mozilla/pdf.js/blob/0a4153349dc473ba950fc17941c5ca7eda43c1de/LICENSE). Из архива извлекаются только проверенные `build/pdf.mjs`, `build/pdf.worker.mjs` и `LICENSE`. Исходные заголовки Mozilla сохраняются в объединённом worker. Файлы установленного стороннего расширения не используются.

`engine.json` фиксирует хэши входов и SHA-256 worker `2158e4f989f5bd0668e9b890e92e22de4db51acd03a4ed81148662087f0ab692`, размер worker 1 662 547 байт. Хэши версии PDF.js, архива, исходных модулей и лицензии сохранились. Новый хэш worker учитывает TypeScript-адаптер и явную обработку отказа в ресурсах без исключения из `finally`. Две сборки в разных временных каталогах дали побайтово одинаковый worker. Worker пакета с API совпал побайтово с TypeScript-кандидатом. Фиксируется worker, а внешний ZIP VSIX может различаться служебными метаданными. Повреждённый вход отклонён до создания VSIX. Для автономного повторения исходный архив оставлен рядом с VSIX в игнорируемом `dist/`. Работа расширения и его упаковка из локальных входов обходятся без скачивания.

В [Mozilla GHSA-hq66-cqwq-w95j](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j) отдельно описана предпосылка включённого scripting при отсутствии ограничивающей CSP. В пакете отсутствует этот интерфейс PDF.js, CSP ограничивает скрипт и сеть. Это проверка применимости к конфигурации, а не независимый аудит парсера.

Команды из `extensions/myself-local-pdf-viewer/`. Локальные пути инструментов задаёт проверяющий. `VSIX` должен указывать на новый путь для сборки или на уже проверяемый пакет для тестов.

- Содержимое VSIX, manifest ID и минимальная версия, лицензия и хэш worker. В тестах прочитаны реальные файлы из VSIX.
- Границы URI, symlink, каталог, неверный заголовок и размер. Тест действия проверяет отмену диалога, игнорирование аргументов и передачу байтов только действующей панели с правильным токеном.
- Извлечённый из VSIX `activate()` вернул API v1. Тесты проверили байты подмассива при синхронном изменении исходного буфера, недопустимые и слишком большие входы, конкуренцию с picker, отмену при dispose, устаревшую панель и отказ при сбое создания панели. - PDF с синтетическим действием печати и внешней ссылкой не вызвал печать, запрос или открытие окна. Отдельная синтетическая попытка соединения из worker вызвала нарушение `connect-src` и не дошла до сети.

Проверка ZIP и `git diff --cached --check` прошли. Зафиксированный в репозитории TypeScript 7.0.2 проверил оба строгих NodeNext-проекта с отдельными библиотеками DOM и WebWorker. Из корня запущен `pnpm run eslint 'extensions/myself-local-pdf-viewer/**/*.{ts,cts,mts}'`. Проверены 10 файлов по штатной конфигурации. Декларация PDF.js проверена TypeScript, штатный ESLint исключает декларации расширений. ## Передача интегратору

Самостоятельная команда открывает picker. После независимой package/security-приёмки библиотека подключает API отдельным изменением по проверенному ID расширения и зарегистрированному PDF ID. Библиотека владеет канонизацией и повторной сверкой SHA‑256 импортированной копии. Приёмка должна проверить штатную установку и реальный webview IPC, включая Restricted Mode с действующим Workspace Trust. Поддержка произвольных PDF и жёсткая квота памяти остаются за границами кандидата.

### API библиотеки v1

`activate` возвращает `{ apiVersion: 1, openBytes(bytes: Uint8Array): Promise<boolean> }`. Обе точки входа передают принадлежащий расширению `ArrayBuffer` в один контроллер. Он загружает проверенный worker, заменяет предыдущую панель и передаёт байты по ready-токену активной панели. Picker и API используют один токен текущего запроса. Пока он занят, второй запрос API возвращает `false`, а picker не открывает второй диалог. Dispose сбрасывает токен и закрывает панель. API открывает панель с `{ viewColumn: Beside, preserveFocus: true }`. Picker сохраняет обычное открытие рядом с редактором.

Библиотека по явному действию подтверждает зарегистрированный ID PDF, канонический локальный файл и сохранённый SHA-256. Затем она активирует установленное расширение с точным ID `myself.myself-local-pdf-viewer` и проверяет `apiVersion` и наличие `openBytes`. Метод проверяет фактический тип и длину Uint8Array перед выделением памяти. Представления на SharedArrayBuffer, отсоединённые буферы и подставные объекты отклоняются. Владелец панели синхронно копирует точный диапазон в собственный буфер и проверяет заголовок в копии до первого ожидания. Контракт не передаёт путь, URI или управление настройками панели. `true` означает, что панель приняла документ. Ошибки рендера остаются сообщениями внутри просмотра. Отказ валидации, занятость контроллера и недоступность панели дают `false`.

В одном extension host этот публичный API подходит. Точный ID и версия API выбирают получателя, но не удостоверяют код неизвестного VSIX и не идентифицируют вызывающее расширение. Поэтому релизная проверка пакета и валидация входа остаются обязательными. При другом extension host [реализация Extension.activate](../../src/vs/workbench/api/common/extHostExtensionService.ts) отклоняет активацию и не предоставляет exports. Интеграция должна показать недоступность без перехода на URI, внешнюю команду или автоматическую установку. Библиотека и её манифест в этой задаче не менялись.
