# Локальная работа с PostgreSQL

Задача №24. Ветка `codex/local-postgres-workflow` от `7f3a643fe9d`. Проверен установленный клиент `Supabase.postgrestools` 1.4.0 чтением манифеста и `out/*.js`. **Действие SQL для этой версии заблокировано**. Холодный старт может обратиться к GitHub, а в клиенте отсутствуют команды выполнения запроса и просмотра схемы. Изменение ограничено этим отчётом.

## Подтверждённая работа CLI

Интегратор проверил PostgreSQL 18.1 и `psql -X -v ON_ERROR_STOP=1` на временном кластере с выключенным TCP и приватным Unix-сокетом. Прошли запрос, чтение `information_schema` и проверка отката транзакции. Это подтверждает локальный путь CLI. Подключение установленного LSP и обработчик SQL внутри редактора в этот прогон не входили. [Интеграционный отчёт](development-wave-2.md)

### Локальный сервер и отключение сети

Для отдельной диагностики в изолированном доверенном профиле клиент принимает заранее установленный исполняемый `postgres-language-server` через строковый абсолютный путь в `postgres-language-server.bin` или объект со значением на платформу. В одном корне клиент ищет конфиг `postgres-language-server.jsonc`, затем `postgrestools.jsonc`; можно указать `postgres-language-server.configFile`. В multi-root выбор бинарника глобальный, относительный путь к бинарнику отклоняется, а папке требуется один из корневых конфигов или общий абсолютный `configFile`. В режиме одного файла сессия не создаётся. Этот способ выбора бинарника оставляет описанный сетевой путь. В проверенной командной среде `psql` есть в `PATH`, оба имени LSP-бинарника в `PATH` не обнаружены. Другие места установки не проверялись. [Контракт бинарника и проекта](https://github.com/supabase-community/postgres-language-server-vscode/blob/main/README.md)

Строгий способ исключить эту фоновую сеть в 1.4.0 — не допустить активации расширения. Для нативной приёмки допустим изолированный профиль без этого расширения или новый изолированный запуск со штатным `--disable-extension supabase.postgrestools`. Последний флаг непостоянный и действует при открытии нового окна. Изменения личного профиля для этого аудита не выполнялись. Запущенный LSP может читать схему для анализа SQL через секцию `db`; это отдельная возможность сервера и не открывает пользовательское исполнение SQL или обозреватель схемы. Локальная работа клиента с конкретным сервером и схемой пока не проверена. [Описание возможностей LSP](https://github.com/supabase-community/postgres-language-server-vscode/blob/main/README.md#setting-up-your-project)

Манифест 1.4.0 не объявляет поддержку Restricted Mode; в коде клиента нет собственного обращения к `workspace.isTrusted`. Форк по умолчанию блокирует такое расширение с исполняемой точкой входа в Restricted Mode, если не задано переопределение. Это проверка платформы, а не гарантия безопасности клиента в доверенном окне. См. `ExtensionManifestPropertiesService.getExtensionUntrustedWorkspaceSupportType`.
