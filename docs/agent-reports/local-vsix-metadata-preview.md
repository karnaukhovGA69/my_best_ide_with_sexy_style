# Проверка метаданных локального набора VSIX

Ветка `codex/local-vsix-metadata-preview`, код `6c6334d748863b17229a468449b5a464baa77730`, база `24e82b41e4fae2c9fd840fa7a975f878c20f200c`. Требуется staging из `7abae5c32e1c3c5458f8926d0bf10fad4e2e6184`. Изменения интерфейса ограничены `myselfVsixSets`, серверные изменения ограничены ранее созданным staging и его тестами. Ветка ждёт desktop transport и независимую проверку.

## Поведение

**Preview Local VSIX Set…** по-прежнему сначала показывает декларации из JSON. При нажатии **Inspect VSIX Metadata** файлы проверяются последовательно. Диалог показывает фактический ID, версию и SHA-256 и отдельное совпадение или расхождение для каждого поля. Требование к версии редактора показано как декларация пакета. Отсутствующие файлы и недоступные результаты имеют собственные статусы. Подпись, совместимость платформы и безопасность установки остаются непроверенными. Существующая кнопка **Check SHA-256** и её последовательное чтение сохраняются.

Используется зарегистрированный провайдер `file:` без активации. Имя каждого файла повторно проверяется как допустимый basename, а его местоположение вычисляется относительно каталога выбранного манифеста. Статические ссылки и специальные файлы отбрасываются до вызова native inspector. Допустимо до 32 MiB исходного файла и до 128 MiB в сумме. До каждого вызова резервируется наблюдаемый размер источника и один байт проверки роста. Резерв учитывается даже после ошибки. Серверу передаётся предел, который он проверяет на исходном файле до чтения. Дополнительный повторный хэш временных копий и ограниченный разбор ZIP входят в работу staging, сверх объёма чтения исходников.

Замена провайдера, отмена и изменение наблюдаемых метаданных каталога до публикации исключают запоздавший результат. Отдельный файл с изменившимся размером, типом или временем метаданных пропускается. Результаты представляют снимки прочитанных файлов. Проверки по пути не образуют атомарного снимка всего каталога. Родительские ссылки и OS mounts регулируются системным разрешением путей. Работа не использует URL, галерею, установку или запуск расширений.

## Точные точки подключения

Рабочая область экспортирует `registerLocalVsixSetPreviewAction(createInspector)` из `myselfVsixSets/browser/localVsixSetPreview.contribution.ts`. `createInspector(accessor)` синхронно захватывает существующий desktop-сервис и возвращает функцию `(resource: URI, maxBytes: number, token: CancellationToken) => Promise<ILocalVsixInspection | undefined>`. Вызов канала должен находиться внутри возвращаемой функции, чтобы произойти только после явного выбора проверки. Прежняя side-effect регистрация заменена этим экспортом. Desktop entrypoint должен подключить desktop-адаптер. Ресурс локализации остаётся существующим.

Desktop-адаптер вызывает `sharedProcessService.getChannel('extensions').call('inspectLocalVsixV1', [resource, maxBytes], token)`. Native сторона вызывает экспорт `inspectLocalVsixV1(source, maxSourceBytes, token)` из `platform/extensionManagement/node/localVsixStage.ts`. Эту операцию предоставляет только канал локального shared process. Операция принимает URI, ограничение размера и штатный token. Результат содержит только `id`, `version`, `engine`, `sha256` и `bytes`. Он возвращается после закрытия и удаления снимка. Ошибки инспекции сворачиваются в недоступный результат, отмена возвращается как отмена. Directory path, данные архива, raw errors, capability tokens и Apply отсутствуют.

## Проверки

На macOS ARM64 с Electron Node 24.22.1 под запретом сети прошли 33 теста основной contribution и 13 тестов Node staging в отдельной esbuild-обвязке с Mocha TDD. Проверены явное согласие, точный URI и предел, раздельная сверка полей, отсутствие автоинспекции, специальный файл, невалидный basename и схема, оплата неудачной попытки из общего бюджета, замена провайдера и каталога, поздний ответ после отмены, одинаковые байты и очистка до возврата DTO. Для файлов вклада и staging целевые TypeScript и ESLint без ошибок. При внешней конфигурации ESLint отключалось правило `local/code-import-patterns`. `git diff --cached --check` прошёл. Тесты интерфейса используют настоящий реестр команд и подставные диалоги, файловый провайдер и транспорт. Тесты staging используют синтетические архивы и отдельный временный каталог. IDE, пользовательские архивы и установка в проверках не использовались.

После подключения требуются интеграционный прогон фактического desktop вызова, отрицательная проверка remote transport, подтверждение отмены через канал и пакетный нативный smoke. Общие entrypoints и сервисы принадлежат интегратору. Срез стоит интегрировать вместе со staging и проверенным транспортом.
