# Внутренняя подготовка локального VSIX

Ветка `codex/local-vsix-stage`, база `36dbb82e26dd4ad538e63e295a5af73bfcdf3ddf`, код `7abae5c32e1c3c5458f8926d0bf10fad4e2e6184`. Срез предназначен для будущего потребителя в native/shared process. Ветка остаётся отдельной до подключения реальной проверки перед установкой.

## Связь исходных байтов, суммы и метаданных

`withStagedLocalVsix` принимает явно выбранный абсолютный `file:` URI без authority, query, fragment или сегментов обхода пути. Поддержка зависит от POSIX `O_NOFOLLOW`, `O_NONBLOCK` и UID. Исходный путь проверяется до открытия. Дескриптор должен соответствовать свежим метаданным обычного файла. Для источника применяется лимит 32 MiB. Копирование выполняется блоками до 64 KiB, учитывает короткие записи, проверяет EOF дополнительным байтом и повторно сверяет источник и запись в каталоге. Исходный файл открывается только для чтения.

Снимок создаётся через `mkdtemp` в отдельном каталоге владельца с режимом 0700 и эксклюзивным файлом с запрошенным режимом 0600. SHA-256 учитывает только успешно записанные блоки. Перед разбором снимок повторно хэшируется через тот же открытый дескриптор, результат сравнивается с хэшем записи. Метаданные ZIP читаются с этого же дескриптора. Перед передачей callback сверяются размер, inode, времена, владелец, число ссылок, тип и имя снимка. Смена исходного пути после подготовки не меняет копию. Callback получает внутренний путь только на срок своего вызова. Отмена до callback, ошибка подготовки и завершение callback закрывают дескрипторы и убирают конкретный временный файл и его каталог. Удаление каталога не рекурсивное. Если очистка не удалась, возвращается отдельная ошибка. Аварийное завершение процесса требует будущего учёта и уборки временных копий.

## Ограниченный разбор

Штатный `getManifest` использует `base/node/zip.buffer`, который накапливает распакованный поток без лимита и завершает поиск без проверки дубликатов. Штатный `validateZip` ограничивает заявленное число и объём записей и не даёт ограниченного чтения метаданных. Новый локальный ридер лениво подключает существующий yauzl через `RandomAccessReader` с границами текущего дескриптора. Он проверяет не более 4096 записей и имён, глубину и размеры путей, допустимые типы и методы ZIP, конфликты регистра и нормализации, а также заявленные пределы распаковки 64 MiB на запись и 128 MiB на архив.

Распаковывается только `extension/package.json`. Лимит результата 64 KiB, лимит сжатой записи 65 KiB. Проверяются фактический размер, CRC-32, UTF-8, строгий JSON и дубликаты ключей, включая вложенные объекты. Из манифеста возвращаются канонический ID, точная версия SemVer и синтаксически допустимое `engines.vscode`. ZIP остаётся с исходными байтами. Метаданные остальных записей проверяются без их распаковки. Проверка `extension.vsixmanifest`, платформы, фактической совместимости движка, подписи и политики остаётся обязательной для будущего потребителя.

Граница отражает временный снимок в сотрудничающем процессе. POSIX-флаги запрещают следовать ссылке в конечном компоненте исходного пути. Родительские ссылки и подключённые файловые системы остаются частью разрешения путей ОС. Повторные stat и частный каталог не изолируют данные от произвольного процесса того же пользователя. Потребитель должен удерживать свой lease и повторно удостоверить байты на границе фактической распаковки. Профиль, одноразовые IPC tokens, запись реестра, запуск и установка в этом срезе отсутствуют.

## Проверки и передача

11 синтетических тестов прошли на macOS ARM64 с Node 24.22.1 и запретом сети через `sandbox-exec`. Для прогона использованы отдельная esbuild-обвязка, временный `TMPDIR` и штатный Mocha TDD. Проверены совпадение исходных и сохранённых байтов с SHA-256, подмена исходного файла после подготовки, изменение источника при копировании, изменение снимка до повторного хэширования, лимиты, недопустимые ссылки и типы ZIP, CRC, дубликаты JSON, имена, отмена и очистка при ошибке callback. TypeScript Compiler API с параметрами `src/tsconfig.json` и целевой ESLint без ошибок. При внешней конфигурации ESLint отключалось правило `local/code-import-patterns`. `git diff --cached --check` прошёл. Node вывел предупреждение о старом использовании `Buffer()` в тестовом графе зависимостей, новые исходники используют `Buffer.alloc`, `Buffer.allocUnsafe` и `Buffer.from`. Пользовательские архивы и окна IDE не использовались. Полная сборка не выполнялась.

Дальнейшая граница для Apply включает привязку к живому IPC-сеансу и профилю, lease и повторную сверку байтов в действующем extractor, полную проверку формата ZIP, платформы и политики, согласование свободного слота со штатной установкой и CLI. Подключение общих контрактов и entrypoints остаётся у интегратора. Этот коммит сам по себе не добавляет пользовательское действие.
