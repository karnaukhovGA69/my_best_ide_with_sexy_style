# log-session-budget

Статус: ГОТОВО к интеграции в следующий пакет. Владелец: чат упрощения Myself IDE. Ветка: agent/log-session-budget. База: main 5f88b8b3d41. Claim: b1c8e979462. Код и тесты: 28c7873555e.

Область: src/vs/platform/log/node/diagnosticLogSessionRetention.ts, src/vs/platform/log/test/node/diagnosticLogSessionRetention.test.ts, src/vs/code/electron-utility/sharedProcess/contrib/logsDataCleaner.ts и этот отчёт.

Результат: существующий desktop shared-process cleanup через 10 секунд после старта теперь удаляет старые timestamped log sessions по общему наблюдаемому бюджету 100 MiB, возрасту последнего изменения 7 дней и прежнему пределу 9 архивных сеансов. В размер входят вложенные файлы и текущий сеанс. Удаляются самые ранние имена сеансов. Текущий/более новый сеанс и активность за последние сутки сохраняются даже при превышении бюджета. Произвольный --logsPath без timestamp не запускает удаление соседей. История, workspaceStorage и другие не-сеансовые каталоги не обходятся. Архивные Output/extension logs внутри удаляемого старого сеанса удаляются вместе с ним, как в прежнем cleaner; активный Output не ограничивается этим изменением.

Сканирование ограничено 10000 элементами и глубиной 16; неполные/нечитаемые сеансы и symlinks сохраняются. Повторное сканирование кандидата проверяет inode/device/последнюю активность/размер перед удалением. Нет постоянного watcher/опроса/сборщика. Native per-channel rotation остаётся без изменений. Это best-effort бюджет архивов при старте, не жёсткая квота всех живых логов: активные/недавно изменённые/неполные сеансы могут превышать 100 MiB; приложение за долгий сеанс может нарастить логи до следующего старта. Повторная проверка уменьшает гонку с писателем, но не является атомарной блокировкой внешнего процесса.

Проверки: 19 Mocha node tests passed (13 новых session-retention + 6 прежних channel-retention), на временных каталогах и sparse files. Проверены возраст/размер на границах, вложенные текущие логи, count retention, recent/future sessions, сторонние каталоги, файлы с именами сеансов, symlink root/current/child, предел глубины, повторный cleanup. Runner — целевой esbuild bundle + Mocha с disposable tracking, без полного Electron runner. Targeted ESLint 3 файлов прошёл. Узкие TypeScript syntactic/semantic diagnostics 3 файлов с ambient declarations и Node types — 0; первый вариант harness без Node types выявил только неполную конфигурацию harness, исправлено без ослабления compiler flags. git diff --check прошёл. Собственные зависимости установлены offline из lockfile без scripts; корневые inputs не менялись. Полный client typecheck/build/native smoke/release не запускались.
