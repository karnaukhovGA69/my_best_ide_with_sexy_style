# Восстановление импорта и блокировка удаления пакетов LSP

Часть задачи [#4](https://github.com/karnaukhovGA69/my_best_ide_with_sexy_style/issues/4). Ветка `agent/lsp-managed-leases` от `b152bd7b33a`. Целевая платформа macOS ARM64, локальное хранилище профиля IDE.

Раньше принудительное завершение Extension Host во время импорта оставляло скрытые файлы до 640 МиБ. Теперь **Refresh** очищает временные каталоги нового формата после освобождения блокировки импорта. Во время активного импорта Refresh оставляет его файлы на месте. При занятой блокировке удаление сообщает, что пакет используется. После ошибки удаления уже скрытого пакета Refresh повторяет очистку.

- `src/lease.ts` использует Darwin `O_EXLOCK` и `O_NONBLOCK`. Дескриптор удерживает блокировку ядра. Проверяются тип файла, владелец, режим, число ссылок и совпадение inode с записью каталога. Постоянные файлы блокировок сохраняются, чтобы все окна открывали один inode. Числовой флаг ограничен macOS ARM64. [Apple open(2)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/open.2.html) · [Apple flock(2)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html)
- `src/store.ts` удерживает одну блокировку импорта с момента до создания `.import-v2-*` до завершения публикации или очистки. Refresh очищает каталоги этого формата только под той же блокировкой. Удаление и повторная уборка используют блокировку UUID и отдельное имя `.removed-v2-*`. Перекрывающиеся операции получают явный результат «занято» и могут повториться после освобождения.
- `src/extension.ts`, `test/store.test.cts` и `test/vsix.test.cts` подключают Refresh и сообщение о занятости, проверяют сценарии на реальных локальных процессах и собранном расширении с имитацией API IDE.

Хранилище общее для окон обновлённого клиента. Версия 0.1.1 умеет удалять опубликованные UUID-пакеты и не участвует в новой блокировке. Раздельные имена временных директорий ограждают текущий импорт и удаление от старого Refresh. Старые `.import-*` остаются на диске. Refresh умеет повторять удаление старых `.removed-<UUID>`. Перед запуском пользовательских пакетов нужен отдельный layout или миграция, исключающие доступ старого Remove к исполняемому дереву. Блокировки временных каталогов рассчитаны на сотрудничающие экземпляры клиента и локальную ФС, например APFS.

## Что требуется перед Start

1. Взять блокировку пакета до чтения манифеста и проверить пакет после её получения. Удерживать блокировку до подтверждённого выхода процесса. Опыт с синтетическим дочерним процессом показал, что унаследованный дескриптор удерживает блокировку после SIGKILL родителя до закрытия последней копии. Произвольный сервер может сам закрыть унаследованный дескриптор. Первый запуск требует проверенного владельца блокировки, который остаётся жив до подтверждённого выхода сервера, либо консервативного отказа от запуска и удаления при неопределённом состоянии. Остановка по PID из старой записи и уборка по времени не подходят.
2. Повторять алгоритм 0.1.1 для дерева версии 1. Исходные относительные пути с разделителем `/`, длина и SHA-256 байтов каждого обычного файла образуют кортежи. Кортежи сортируются по исходной строке пути, сериализуются через `JSON.stringify`, затем хэшируются как UTF-8. Детерминированная проверка должна покрывать все вспомогательные файлы, отклонять лишние файлы, ссылки и спецфайлы, перепроверять тип и архитектуру выбранного бинарника. В версии 1 пустые каталоги, режимы и xattrs находятся за пределами хэша. Проверять их по отдельной политике или добавить явно версионированный формат. Для файловых систем, меняющих представление имён, хранить исходные имена из ZIP и сверять их с однозначно сопоставленными файлами. Не сортировать по локали и не менять нормализацию при повторном вычислении.
3. Пакет 0.1.1 хранит только digest исходного ZIP и помечен `requires-assessment`. Перед исполнением заново запросить исходный ZIP и совпадение его SHA-256 либо запросить повторный импорт в новом формате. Для происхождения получать ожидаемый digest или подпись из независимого источника. Снимать quarantine с открытого дескриптора того же пользовательского файла, который хэшируется, через `fgetxattr`. Различать присутствующий, отсутствующий и неизвестный атрибут. Сохранить проверенные данные вне payload, перенести имеющийся атрибут через OS API и проверить фактическую системную оценку перед запуском. Отсутствие сведений о старом импорте сохраняет `requires-assessment`. Результат привязать к UUID, относительной точке входа и обоим хэшам. Gatekeeper может использовать сетевое получение билета. Отдельно подтвердить сценарий при отключённой сети и обработку отказа ОС. [Apple fgetxattr(2)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/getxattr.2.html) · [Apple notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)

## Воспроизведение

На macOS ARM64 прошли 32 теста под запретом сети с Node 24.22.1 из Electron, целевой TypeScript и ESLint. Исполняемые файлы из ZIP использовались как данные. Полный пакет IDE и её окно не запускались.

```sh
./node_modules/.bin/tsc -p extensions/myself-language-servers
node extensions/myself-language-servers/package-vsix.mts .build/lsp-lease-test
LANGUAGE_SERVERS_TEST_VSIX="$PWD/.build/lsp-lease-test/myself.myself-language-servers-0.1.1.vsix" \
  ELECTRON_RUN_AS_NODE=1 /usr/bin/sandbox-exec -p '(version 1) (allow default) (deny network*)' \
  '/Applications/Nerded Code.app/Contents/MacOS/Nerded Code' --test extensions/myself-language-servers/test/*.test.cts
git diff --check
```

Для ручной приёмки использовать отдельный профиль и два окна с одной версией клиента. В первом окне остановиться на выборе бинарника из тестового ZIP. Во втором нажать Refresh и убедиться, что выбор и файлы первого импорта сохранились. Прервать синтетический процесс импорта штатным тестом SIGKILL, затем проверить, что Refresh удаляет его временную папку и сохраняет предыдущую установку и каталог старого формата. Для удаления адресный тест удерживает блокировку во втором процессе и симулирует ошибку диска после переименования. Окно с открытым пользовательским проектом для проверки не требуется.
