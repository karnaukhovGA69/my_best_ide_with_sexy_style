# Проверка сохранённого пакета языкового сервера

Ветка `codex/lsp-package-verify`, база `8ee7ab8c96570bd136356db6396ffde6f5326a13`, код `0e5fbb938b439d935a80468cac6c4b4efb6a6cce`. Продуктовые изменения ограничены отдельным расширением `extensions/myself-language-servers`. Готово к независимой проверке. Версия VSIX остаётся 0.1.2 до решения интегратора.

## Поведение

В Explorer, в разделе **Language Server Packages**, у выбранного пакета появилась кнопка **Verify Language Server Package**. Команда принимает элемент списка и повторно читает пакет по его UUID под той же блокировкой, которую использует Remove. Список, импорт и обновление списка не запускают проверку. При отмене текущая операция освобождает открытые дескрипторы и блокировку, уведомление о результате не появляется.

Сверяются схема манифеста, UUID, структура каталога, имена, типы и байты файлов. Хэш в исходном формате v1 включает отсортированные кортежи из точных строк путей, размеров и SHA-256 файлов. Проверяются все обычные файлы в payload, включая соседние ресурсы. Действуют пределы исходного импорта в 4096 путей, 256 MiB на файл и 512 MiB содержимого дерева. Данные хэшируются блоками до 64 KiB. Выбранная точка входа сверяется с точным именем и проверяется существующим разбором ARM64 Mach-O на уже открытом дескрипторе. Стабильность проверяется по метаданным открытого файла и его записи в каталоге, затем метаданные дерева проверяются повторно перед результатом.

Занятая блокировка, повреждённый манифест, лишние файлы рядом с payload и манифестом, ссылки, спецфайлы, неподходящая точка входа, ошибки чтения, превышение лимитов и изменение в ходе чтения имеют отдельные сообщения. Расхождение агрегатного хэша v1 обнаруживает добавленные, удалённые и изменённые файлы внутри payload. Сам формат не хранит перечень кортежей, поэтому по нему нельзя различить эти случаи или назвать конкретный файл. Если сумма расходится и имена допускают преобразование Unicode, вывод указывает, что исходное написание имён подтвердить невозможно. Пустые каталоги, режимы и расширенные атрибуты не входят в хэш v1, хотя проверка применяет отдельные ограничения типов и доступа. Старые правила списка сохраняются, поэтому пакет с уже скрытым повреждённым манифестом или отсутствующей точкой входа может не получить кнопку после обновления списка.

## Граница проверки

Совпадение подтверждает внутреннюю целостность прочитанных данных относительно сохранённого манифеста. Проверка заголовка подтверждает наличие подходящего формата и архитектуры. Внешняя подпись, издатель, совместимость загрузчика, оценка ОС и разрешение на запуск остаются непроверенными. Результат не сохраняется как разрешение на запуск. Расширение не загружает, не запускает, не применяет chmod, не изменяет payload или архив. Для координации используется существующий постоянный файл блокировки UUID. Пакетные файлы открываются только для чтения, с запретом перехода по ссылке в конечном компоненте. Координация распространяется на окна, участвующие в текущем протоколе блокировки, а повторные stat остаются наблюдениями. Операции через старую версию расширения или сторонний процесс не образуют атомарного снимка дерева.

## Проверка и интеграция

На macOS ARM64 с Electron Node 24.22.1, под `sandbox-exec` с `deny network*`, прошли 42 теста Store, импорта и существующей stdio-фикстуры. Среди них 10 новых тестов проверки пакета и проверка совместимости с реальным импортом. Дополнительно прошёл один тест распакованного временного VSIX с подставным API IDE. Он проверяет регистрацию команды, отсутствие автоматического чтения, отбрасывание постороннего аргумента, успех, отмену, расхождение и исходное удаление. Целевой TypeScript 6.0.3 проверил расширение без ошибок. Целевой ESLint прошёл с отключением `local/code-import-patterns` для внешней конфигурации. `git diff --cached --check` прошёл. Временные артефакты удалены. Рабочий профиль, пользовательские архивы, окна и полная сборка IDE в тестировании не использовались.

В checkout с установленными закреплёнными зависимостями используется обычный набор команд расширения:

```sh
pnpm exec tsc -p extensions/myself-language-servers
node extensions/myself-language-servers/package-vsix.mts .build/lsp-verify-test
LANGUAGE_SERVERS_TEST_VSIX="$PWD/.build/lsp-verify-test/myself.myself-language-servers-0.1.2.vsix" \
  /usr/bin/sandbox-exec -p '(version 1) (allow default) (deny network*)' \
  node --test extensions/myself-language-servers/test/*.test.cts
```

Нового подключения в ядре и новых зависимостей нет. После независимой проверки интегратору предстоит отдельно обновить версию и собрать поставочный VSIX. Нативная приёмка использует отдельный профиль и синтетический архив. Проверить появление кнопки у пакета, успешную проверку, изменённый ресурс, занятость при блокировке из другого окна и отмену. В пакетах с недоступным исходным представлением имён следует ожидать отказа от подтверждения целостности.
