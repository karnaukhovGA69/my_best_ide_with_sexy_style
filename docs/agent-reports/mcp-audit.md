# MCP audit

Статус: аудит завершён, готов к review интегратором. Владелец: отдельный агент задачи `mcp-audit`; ветка `agent/mcp-audit`. База: `d430382a16189ec1ac8a1fc907c7fac852dab1a7` (main с правилами и шестой итерацией). Дата: 2026-11-04. Единственный изменённый файл — этот отчёт. Runtime, общие entrypoints, build и области других агентов не изменены.

Результат: проверяемая статическая карта загрузки MCP, границ удаления и будущих проверок. Сборка и запуск приложения в этой задаче не выполнялись. Ниже «загружается» означает доказанную связь с entrypoint/регистрацией на этой базе, а не измерение процесса или поставляемого bundle. Все пути относительно корня форка; символы надёжнее номеров строк при последующей интеграции.

## Выводы для следующего этапа

1. MCP не удалён. `chat.mcp.access: none` прекращает запуск discovery и скрывает коллекции реестра, но не снимает регистрации сервисов, startup contributions, extension-host RPC, профилей и IPC. Это переопределяемый default, а не продуктовый запрет.
2. Даже при `none` остаются конкретные цепочки создания: eager `McpWorkbenchService` → `queryLocal()` → management/scanner; `McpResourceFilesystem` в `BlockRestore` → `IMcpService`; локальный gateway tool broker в `AfterRestored` → `IMcpService`. В `McpService` есть первый отложенный пересчёт через 500 ms. Сам факт конструктора gateway не означает открытый порт: HTTP listener создаётся в `createGateway()`.
3. Нельзя удалить `contrib/mcp` одним PR: на три MCP-каталога есть 77 внешних TS-файлов-потребителей в `src`, если учитывать относительные import-пути и исключить только каталоги `test`. Это статическая инвентаризация, включая type-only и выключенные Sessions/Agent Host, а не 77 работающих функций. Метод воспроизведения ниже.
4. Самые опасные общие потребители: `AuthenticationQueryService`, `MainThreadAuthentication`, JSON settings renderer, configuration/profile model, ext-host API/protocol. Ошибка здесь может нарушить авторизацию, настройки или активацию обычного расширения задолго до вызова MCP.
5. Отдельная граница сети: eager desktop gallery manifest принимает `chat.mcp.gallery.serviceUrl`, не проверяя `chat.mcp.access`. Без `product.mcpGallery` и без пользовательского URL default manifest равен `null`; с URL без версии выполняется определение версии через HTTP. Не утверждать, что на компьютере пользователя были запросы: пользовательские настройки и сетевой трафик не исследовались.
6. Copilot extension и standalone Sessions/Agent Host исключены правилами публичной упаковки. Их исходники/зависимости всё ещё существуют; правила фильтрации не доказывают отсутствие каждого встроенного фрагмента в bundle или каждого транзитивного пакета в ASAR. Текущий бинарный артефакт этим аудитом не проверялся.

- Каталог: `src/vs/workbench/services/mcp/browser/mcpGalleryManifestService.ts` → `getAndUpdateMcpGalleryManifest()` читает `chat.mcp.gallery`; `src/vs/platform/mcp/common/mcpGalleryManifestService.ts` → `createMcpGalleryManifest()`/`checkVersion()`; `mcpGalleryService.ts` выполняет запросы каталога. `getDefaultMcpGalleryManifest()` возвращает `null` при отсутствии product config. ## 5. Extension API, settings, профили и общие UI

**API — отдельный совместимый слой.** `src/vs/workbench/api/browser/extensionHost.contribution.ts` импортирует `mainThreadMcp.ts` с `@extHostNamedCustomer(MainContext.MainThreadMcp)`. `api/common/extHost.common.services.ts` регистрирует `IExtHostMpcService` eager; именно `Mpc` — написание существующего токена. `api/node/extHost.node.services.ts` подключает Node implementation. `api/common/extHost.api.impl.ts` получает сервис и устанавливает `ExtHostContext.ExtHostMcp` в RPC protocol, а затем экспортирует `vscode.lm.registerMcpServerDefinitionProvider`, MCP classes и proposed APIs. Формы/идентификаторы RPC находятся в `api/common/extHost.protocol.ts`; сериализация — `extHostTypeConverters.ts`, публичные классы — `extHostTypes.ts`.

`lm.registerMcpServerDefinitionProvider` уже есть в стабильном `src/vscode-dts/vscode.d.ts`, а не только в `vscode.proposed.mcpServerDefinitions.d.ts`/`vscode.proposed.mcpToolDefinitions.d.ts`. Выкинуть весь `lm` namespace или бросать ошибку при каждой регистрации — риск сломать активацию расширения, у которого MCP лишь дополнительная возможность. Предлагаемый переходный контракт: оставить API symbols/classes и disposable registration, не вызывать provider callbacks и не публиковать runnable definitions; enumeration пустая, события не работают в фоне; явный запуск gateway/MCP отклоняется понятной unsupported ошибкой. Это предложение, не реализованный stub; документировать ограничение для MCP-only расширений. Extension host, commands, languages/completion/formatting, authentication и ручной VSIX не удалять.

root = Path.cwd()

    if '/test/' in relative or relative.startswith(prefixes):
