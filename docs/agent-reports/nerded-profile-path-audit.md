# nerded-profile-path-audit

Статус: ПОДТВЕРЖДЁННЫЙ RELEASE BLOCKER, исправление требуется интегратору (владелец product/shared entrypoints). Владелец read-only проверки: release coordinator. Это обнаруженный дефект текущего переименования, не новая фича.

Доказательство: src/mainImpl.ts:60 вызывает getUserDataPath(args, product.nameShort ?? 'code-oss-dev'), затем app.setPath('userData', userDataPath). src/vs/platform/environment/node/environmentService.ts:20 независимо вызывает getUserDataPath(args, productService.nameShort). В src/vs/platform/environment/node/userDataPath.ts default и VSCODE_APPDATA добавляют productName к каталогу данных. Поэтому смена nameShort с Myself IDE на Nerded Code, несмотря на неизменный dataFolderName, меняет обычный user-data root (на macOS Library/Application Support/Myself IDE → Nerded Code). Это противоречит согласованному требованию сохранять пути профиля и не терять видимость настроек при брендинге. user-data-dir QA маскирует этот дефект.

Нужное исправление: стабильное отдельное имя каталога пользовательских данных для этого продукта (прежнее Myself IDE), согласованно использовать его в раннем Electron bootstrap и NativeEnvironmentService/CLI. Внешнее отображаемое имя оставить Nerded Code. Portable, VSCODE_APPDATA и явный --user-data-dir должны сохранить приоритеты; development mode должен остаться code-oss-dev. Не переносить/удалять/объединять пользовательские каталоги и не заменять имя оригинального VS Code. Добавить проверку default existing-profile path и precedence. Точная реализация/новое product поле остаются интегратору.

Это не предположение про branding: обе активные source точки напрямую зависят от изменённого nameShort. Проверено чтением кода; файлов пользователя не менял. Установленные личные грамматики находятся в стабильном extensions root .myself-ide, но текущий новый профиль не должен подменять прежний user data. Публикация и окончательная установка ожидают исправления этого дефекта вместе с icon fix.
