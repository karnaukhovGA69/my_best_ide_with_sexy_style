## Граница первой реализации

1. Выделить **`myself.myself-pdf-export`** как устанавливаемый вручную локальный VSIX. Он владеет экспортным адаптером, проверкой пользовательских параметров, настройками оформления и своими ресурсами. Команда модуля принимает узкий DTO и активируется по явному экспорту. Идентификатор, активация, ресурсы и исполняемые файлы модуля находятся вне подписанного приложения. Редактор документов и библиотека сохраняют собственные manifest, формат текста и управление данными.
2. Сохранить прежние **Export Text as PDF** в File и заголовке `.txt`, а также кнопку **Export PDF** в редакторе документов. File menu реализует существующая тонкая workbench contribution. Публичное расширение располагает `editor/title` и `file/newFile`, прямого аналога `MenubarFileMenu` там нет. Построить один признак доступности для текущего окна по локальному зарегистрированному расширению и актуальной enablement, обновлять его при смене профиля, расширений и enablement. Признак не вызывает активацию и не обращается к marketplace. Скрывать экспортные элементы при недоступном модуле, проверять признак повторно в исполнении обеих команд. В editor host использовать проверяемый признак доступности по сообщению хоста, а не наличие внутренней команды в `getCommands()`. Само открытие редактора не активирует модуль. [Точки расширения меню](../../src/vs/workbench/services/actions/common/menusExtensionPoint.ts), [реестр расширений](../../src/vs/workbench/services/extensions/common/extensions.ts), [сервис enablement](../../src/vs/workbench/services/extensionManagement/browser/extensionEnablementService.ts).
3. Сохранить совместимость `myself.documents.exportPdf`, v1/v2 и `saved/cancelled`. Старые кнопки вызывают единственную команду модуля, например `myself.pdf.exportRequest`. После проверки параметров она передаёт DTO отдельной внутренней команде печати workbench/native bridge. Обе точки входа проверяют признак доступности, чтобы прямой вызов при выключенном модуле завершался до диалога. Наличие VSIX — часть жизненного цикла продукта. Входы вызовов по-прежнему считаются недоверенными, включая extension ID и содержимое DTO. Native host сохраняет собственную проверку входа, фиксированный шаблон, CSP и сессию без сети, системный выбор назначения и безопасную запись. Граница доверия не принимает HTML, CSS, произвольные пути, команды или код из VSIX.
4. Тест поставки проверяет отсутствие VSIX и его runtime-файлов в приложении. Штатное отключение убирает доступ к функции. Удаление освобождает каталог после того, как у версии не останется профильных ссылок и завершится штатная очистка. Удаление с одного профиля сохраняет файлы для второго профиля. Сохранённые PDF и тексты принадлежат пользователю. Штатная очистка уже подтверждена отдельно на Local Data Preview. Автоматический вызов очистки при открытии окна виден в исходниках shared process и ещё требует пакетного подтверждения. [Предыдущая проверка модулей](./development-wave-2.md), [очистка в shared process](../../src/vs/code/electron-utility/sharedProcess/contrib/extensions.ts).

Эта граница делает удаляемыми файлы дополнения и убирает пользовательский экспорт при отключении. В приложении остаётся проверяемый путь печати, включая v1/v2 parser. Вынос дополнительных PDF-параметров или макропарсера можно планировать после подтверждения VSIX. Для этого нужен ограниченный структурный запрос с фиксированными типами блоков и повторной валидацией в main. Сохранение v1/v2 потребуется на переходный период.

| Вариант | Что освобождается | Цена и совместимость |
| --- | --- | --- |
| VSIX с существующей печатью Electron | Каталог модуля вне приложения | Сохраняет PDF и офлайн-путь. Небольшой core bridge и renderer остаются подписанными. |
| Отдельная сборка IDE без PDF | Из release bundle можно исключить adapter, native method и export backend | Дополнительный вариант сборки, подписи и проверки обновлений. Пользователь меняет приложение, сохраняя профиль. |
| Самостоятельный движок экспорта в VSIX | Можно перенести генератор и ресурсы из приложения в удаляемый модуль | Нужен новый проверенный движок, включая пагинацию, Unicode, шрифты и текстовый слой. Desktop Extension Host не предоставляет штатный `webContents.printToPDF` через VS Code API. Добавление своего основного процесса или загрузка JS из установленного VSIX в Electron main нарушит текущую границу исполнения. |

## Просмотр PDF в библиотеке

Библиотечный импорт #15, печать текста и показ готового PDF — отдельные обязанности. У печати есть локальная цепочка с фиксированным HTML. У встроенного просмотра пока нет подтверждённой цепочки в этом форке. В первом срезе #15 достаточно управления импортированными локальными копиями по его собственному контракту. Запись каталога, права на копию и её удаление принадлежат библиотеке.

Будущий **отдельный VSIX просмотра** может владеть своими скриптами, worker, шрифтами и другими ресурсами разрешённого движка. Их размер учитывается по файлам пакета. Профильная очистка может освободить эти файлы отдельно от модуля экспорта и библиотеки. Проверенный ранее сторонний просмотрщик с автоматической печатью исключён из предложения. Для нового кандидата нужна проверка на закреплённом Electron. Базовый браузерный viewer требует подтверждения, что его можно изолировать для этой поверхности. Расширение с собственным renderer требует аудита зависимости и обновлений. В обоих случаях нужны границы декодирования и памяти, отсутствие автоматической печати, выполнения действий из PDF, запроса внешних ресурсов и переходов, закрытие обработчика при выходе или отключении. Существующие настройки webview сохраняют sandbox и CSP. [Статус #15](../feature-roadmap.md).

## Следующее задание и приёмка

Разработчик создаёт один вертикальный срез на синтетическом VSIX в своей ветке. В своей области он реализует узкую экспортную команду и макет проявления enablement в обычном редакторе. Интегратор сохраняет штатные команды и проверяет наличие модуля перед вызовом. После стабилизации #15 разработчик редактора подключает ту же доступность в `myself-documents`. Правка сборки, release notes и миграция пользователя следуют после приёмки. До неё текущий работающий экспорт сохраняется.

Безопасник независимо проверяет закрытие прямого вызова при недоступном модуле, фиксацию origin/назначения, no-network и прежние валидацию/CSP/очистку. QA проверяет в отдельном профиле отсутствие опции без модуля, ручную установку, прежние кнопки, несохранённый текст, v1/v2, отмену, Unicode и настоящий локальный PDF. Затем проверяет Disable, Enable, смену профиля, Uninstall и очистку фактического каталога при сохранённых пользовательских файлах. При возврате на предыдущую сборку DTO и файлы пользователя остаются совместимыми. Механизм автоматической установки не требуется.

В этой ревизии выполнены чтение исходников, проверка ссылок и подсчёт исходников. Сборку, упаковку, установку, нативный экспорт и измерение памяти не запускал.
