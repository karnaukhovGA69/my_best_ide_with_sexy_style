# Выбор интерпретатора из Check Project

Задание `project-readiness-python-action`, направление №1. База `d8c6bacc3b3adfb4792b39869f8736b9c3569e1f`, ветка `codex/project-readiness-python-action`, коммит реализации `0ebe95b4255d1aee6057953ca33dcc5e3226f22b`. Изменения ограничены `src/vs/workbench/contrib/myselfProjectReadiness/**` и этим отчётом.

Кнопка **Choose Python Interpreter…** в **Check Project** появляется, когда штатная команда зарегистрирована и в доверенном локальном окне есть подходящая папка. По нажатию диалог возвращает только сигнал выбора. После закрытия повторно проверяются токен, доверие, ID workspace, состояние окна и состав корней. Только затем вызывается `myself.project.setDefaultPythonInterpreter` без аргументов. Выбор папки и файла, предпросмотр изменений и подтверждение остаются в существующем picker. Он поддерживает настройку интерпретатора по умолчанию при доступной декларации Microsoft Python. В Remote и Restricted Mode действие отсутствует. Показ диалога и закрытие без выбора команду не вызывают.

В манифесте установленного BasedPyright `1.40.2` ключ `python.pythonPath` объявлен строкой с областью `resource`. `Check Project` читает его отдельно, если текущий реестр сообщает о том же владельце `detachhead.basedpyright`, типе и области. **BasedPyright Python Path** и **Default Python Interpreter Setting** показывают независимые наблюдения по каждой папке. В строках отображаются только вид значения и источник, интерполяция переменных и проверка исполняемого файла отсутствуют. При ошибке чтения появляется **Not checked**. В Restricted Mode оба ключа остаются непрочитанными. Кнопка передаёт управление существующему Microsoft Python picker и не выбирает интерпретатор для BasedPyright.

34 целевых теста прошли в Node с Mocha TDD после отдельной сборки файлов suite через esbuild, из них 22 для UI и 12 для модели. Проверены положительный вызов после выбора без передачи аргументов, отсутствие автоматического вызова, прямой запуск в Restricted Mode, пустое и удалённое окно, отсутствие picker, смена workspace или доверия до обработки сигнала, поддельный владелец `python.pythonPath`, приватность настроек и ошибок. TypeScript Compiler API с параметрами `src/tsconfig.json` выдал ноль диагностик в файлах вклада. Целевой ESLint прошёл с отключённым `local/code-import-patterns` для запуска внешней конфигурации. `git diff --cached --check` прошёл.

Новые entrypoint, общий сервис и регистрация i18n не требуются. Сценарий приёмки в общем пакете — открытие Check Project с двумя доверенными локальными корнями, явный переход в picker, отмена выбора и подтверждение сохранения после предпросмотра целевой папки. В нативном окне эту ветку ещё не проверяли.
