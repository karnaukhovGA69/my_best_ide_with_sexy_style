## Что доступно

Действие `myself.project.setDefaultPythonInterpreter` находится рядом с Check Project в меню Terminal и в заголовке Explorer. В многокорневом workspace оно запрашивает явный выбор папки, в том числе когда только одна из нескольких папок локальная. Штатный файловый диалог принимает один файл через схему `file:`. Выбранный локальный путь сохраняется как буквальный абсолютный путь. Путь самого кандидата вклад не проверяет запуском или чтением. В превью видны папка, эффективное значение и его источник, старое значение в целевом слое, новое значение и назначение `.vscode/settings.json`. Перезапись происходит после подтверждения.

Ключ `python.defaultInterpreterPath` принадлежит `ms-python.python` и объявлен строковой настройкой с областью `machine-overridable`. Действие проверяет регистрацию этого ключа и его схему через реестр. Без включённого расширения с подходящей схемой оно объясняет, почему действие недоступно. Зарегистрированный ключ описывает начальное значение. Расширение хранит собственный текущий выбор, и настройка не переключает уже выбранный им интерпретатор. [Манифест Python](https://github.com/microsoft/vscode-python/blob/main/package.json) · [Справочник настроек Python](https://code.visualstudio.com/docs/python/settings-reference)

## Трасса настройки и запись

- `IConfigurationService.inspect` получает `resource: folder.uri`. Текущий источник подтверждается совпадением слоя с эффективным значением. Когда одна папка открыта как workspace, `workspaceValue` представляет настройки этой папки. В многокорневом workspace `workspaceFolderValue` относится к выбранной папке, а `workspaceValue` относится к общему workspace. Активная политика или override текущего сеанса блокируют запись. Совпадающее значение в целевом слое даёт результат без записи.
- Действие сохраняет только `python.defaultInterpreterPath` через `IConfigurationService.updateValue` с выбранным URI и `ConfigurationTarget.WORKSPACE_FOLDER`. Штатный `ConfigurationEditing` вычисляет `FOLDER_SETTINGS_PATH` для этого ресурса и применяет JSONC-правку. Опция `donotNotifyError: true` возвращает ошибку операции без встроенного повторного сохранения или предложения сохранить чужие несохранённые изменения. Вклад показывает собственное сообщение без исходной ошибки.
- Инициализация Workspace Trust завершается до первого picker. Вызов из удалённого окна, неподдерживаемый URI, отмена, потеря доверия, смена корней или изменение настройки до передачи записи блокируют редактирование. Перед `updateValue` повторно сверяются регистрация ключа, снимок значения, доверие и точный текущий корень. Локальный файл-пикер получает только `file:`. Результаты с authority, query, fragment, сегментами обхода или синтаксисом подстановки отклоняются. Аргументы команды игнорируются.
- После подтверждения через прямой `getProvider(Schemas.file)` проверяются корень и два фиксированных компонента `.vscode/settings.json`. Неподходящие типы и замеченные символические ссылки блокируют запись. Провайдер может обратиться к метаданным цели ссылки. Проверка не является атомарной относительно подмены пути и не определяет тип монтирования ОС.
- Проверки отмены действуют до вызова `updateValue`. В публичном API нет отмены уже переданной записи и транзакционной привязки к снимку доверия. `ConfigurationEditing` определяет ресурс в начале своей операции, затем ставит запись в общую очередь. Для строгой гарантии до физического сохранения, включая смену вложенного корня до разрешения ресурса, нужна отдельная сверка и при необходимости доработка общего сервиса интегратором. Такие гонки не считаются покрытыми синтетическим прогоном.

## Подключение

В desktop entrypoint `src/vs/workbench/workbench.desktop.main.ts` рядом с Check Project импортировать вклад.

```ts
import './contrib/myselfToolchain/browser/myselfToolchain.contribution.js';
```

В `build/lib/i18n.resources.json` зарегистрировать `vs/workbench/contrib/myselfToolchain` для `vscode-workbench`. Ключ действия `pickProjectPythonInterpreter` переводится как «Задать интерпретатор Python по умолчанию…». Для кнопки внутри Check Project интегратор может вызвать `myself.project.setDefaultPythonInterpreter` после закрытия диалога проверки и явного выбора этой кнопки. Команде параметры не нужны. Она заново проверяет доверие и предлагает актуальные папки.

## Остальные инструменты

- Для clangd проверить фактический запуск локальной версии расширением и способ конфигурации в multi-root прежде, чем добавлять отдельный выбор сервера. Манифест объявляет `clangd.path` как путь выполняемого файла сервера со scope `machine-overridable`. В проверке нужен установленный локальный VSIX, два корня с разными настройками и подтверждение, что изменение настройки не запускает установку, обновление или перезапуск само по себе. [Манифест vscode-clangd](https://github.com/clangd/vscode-clangd/blob/master/package.json)
- Для компилятора C согласовать конкретного потребителя. У CMake `CMAKE_C_COMPILER` относится к конфигурации дерева сборки, а `compilerPath` в редакторе Microsoft C/C++ относится к IntelliSense и может вызвать опрос компилятора расширением. Для принятия нужен проект выбранного типа с явной привязкой сборки к выбранному компилятору. Проверить фактическую команду сборки и независимость от настроек сервера и других корней. [CMake](https://cmake.org/cmake/help/latest/variable/CMAKE_LANG_COMPILER.html) · [Microsoft C/C++](https://code.visualstudio.com/docs/cpp/customize-cpp-settings/)
