# settings-file-portability

Статус: ГОТОВО к интеграции, требуется одно подключение contribution entrypoint. Владелец: чат упрощения Myself IDE. Ветка: agent/settings-file-portability. База: main 98aa2b043b1. Claim: 28340f48017. Реализация и тесты: c20264b3a19.

Вместо отменённых GitHub OAuth/catalog/backup добавлен локальный перенос settings.json текущего профиля. Export Settings to File и Import Settings from File доступны через Preferences и gear menu. Экспорт — native Save Dialog в JSON. Импорт — native Open Dialog для JSON/JSONC, затем diff текущих и будущих настроек. Отдельные Apply Imported Settings и Discard Settings Import доступны в заголовке preview. До Apply настройки не записываются. Нет запросов к GitHub, сети/сервера/auth service, автоимпорта или скрытой синхронизации.

JSONC допускает комментарии, trailing comma, BOM, Unicode, language overrides. Верхнеуровневые настройки объединяются; значения обычных object settings заменяются целиком, а [language] объединяется по вложенным именам настроек. Сохраняются остальные settings, комментарии и выбранный EOL; результат проверяется на общий предел 2 MiB UTF-8 и вложенность 32. Неверный JSON, не-object root, nonfinite числа и prototype-shaped ключи отклоняются.

Фильтр действует в обе стороны: только зарегистрированные настройки, без MACHINE/APPLICATION_MACHINE/MACHINE_OVERRIDABLE, restricted и ignoreSync. Исключены retired GitHub/chat/MCP/voice/telemetry/sync/inlineSuggest settings, известные credential/token/secret/password/privateKey/apiKey имена и узнаваемые sensitive values (включая вложенные объекты/массивы). Token-color settings сохранены. SecretStorage, auth accounts, SSH-файлы и ключи вообще не читаются. В preview сохраняются существующие локальные секретные settings без их изменения. Фильтр не может распознать произвольный секрет, помещённый вручную в безобидно названную зарегистрированную строковую настройку; гарантия полной классификации произвольного текста не заявляется. Незарегистрированные настройки расширений пропускаются: для переноса таких настроек сначала установить нужные расширения, затем повторить импорт. Показывается количество пропусков. Формат переносит settings.json, не keybindings/snippets/extensions/profile state.

Безопасность записи: один диалог/операция одновременно, один незавершённый preview. Dirty settings запрещают экспорт/импорт/Apply. Apply проверяет профиль, полный исходный текст, exists/etag и повторно dirty state, использует mtime/etag для записи и атомарную замену при поддержке провайдером. Если settings.json отсутствовал — create без overwrite. Ошибка записи сохраняет preview для повторной попытки. Изменённый preview не может молча применить другой snapshot. Смена профиля/изменение source во время Save Dialog отменяют экспорт; активный settings.json не может быть выбран экспортной целью по совпадающему локальному пути. Preview model/provider освобождаются; закрытие preview отменяет ожидающий импорт. Операция не сбрасывает профиль и не меняет другие профили.

Проверены JSONC/Unicode/BOM, размер/depth, сохранение комментариев/CRLF, merge language overrides, фильтрация секретов и retired/machine/unknown settings, no-write preview/cancel/discard, Apply, dirty/profile/stale-file rejection, создание отсутствующего файла и racing creation, write failure/retry, последовательность диалогов, отказ при изменённом preview, очистка ресурсов, видимые меню. Узкие TypeScript diagnostics пяти файлов — 0; ESLint пяти файлов и git diff --check прошли. Первые проверки исправили неверное имя codicon, test-helper import/overload и безусловный запрос atomic write у провайдера без этой capability.
