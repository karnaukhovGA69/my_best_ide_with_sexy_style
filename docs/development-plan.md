[Полное ТЗ](nerded-code-visual-spec.md), [задание агенту](agent-prompts/06-nerded-code-visual.md). Перед назначением проверить текущего владельца UI и свежие claims; не запускать дубликат. Планируемые scopes: `nerded-calm-theme-icons`, `nerded-calm-layout`, `nerded-calm-integration` (последний — текущему интегратору). Назначения этим текстом не сделаны. Реализацию включать в общий пакет перед пользовательской оценкой; отдельного релиза из-за записи ТЗ не требуется.

## Ограничения первого пакета для личного тестирования

Последнее уточнение владельца: первый пакет — локальный редактор. Автоматические обращения в Интернет исключены, включая Git autofetch, обновления, телеметрию, загрузку документации/подресурсов и фоновые каталоги. Обычный системный Git и ручные git/ssh в терминале сохраняются; сеть допустима по явному действию пользователя. Это не сетевой sandbox для произвольных команд или сторонних расширений.

Remote SSH/удалённый сервер редактора и новую автоматизацию удалённых окружений не включать в первый минимальный релиз; существующий код/наработки сохранить. Это временное ограничение поставки заменяет прежнюю активную интеграцию Remote SSH, а не удаляет ручной ssh. GitHub login/catalog/root-clone остаются отложенными.

Сохранить Workspace Trust и запрет автоматического запуска задач/терминала из недоверенных проектов; не ослаблять Electron sandbox, CSP, TLS/SSH verification. Перед новым релизом проверить готовое приложение: untrusted workspace не запускает код автоматически, локальная документация не загружает внешние ресурсы, запуск/простой без действий пользователя не инициируют сеть. Прежние smoke с --disable-workspace-trust этого не доказывают и не заменяют проверки. Состояние реализации этих требований фиксировать отдельно, не объявлять их выполненными только из-за записи в плане.


## Текущий приоритет: редактор и пользовательское тестирование

Последнее решение владельца от 6 ноября 2026: собственный GitHub-вход, подключение аккаунта, специальный каталог репозиториев, выбор корня и clone/open по кнопке ОТЛОЖЕНЫ до пользовательского тестирования редактора. Это заменяет прежнее поручение реализовывать их сейчас. Не продолжать разработку/подключение этих функций к ближайшему релизу, не регистрировать OAuth app и не запрашивать Client ID. Сделанное сохранить в отдельной task-ветке со статусом «отложено по решению владельца»; не удалять и не выдавать за готовую авторизацию. Не добавлять extensions/myself-github в allowlist/build текущего релизного пакета.

Приоритет: остальные согласованные функции обычного редактора и стиль/UI, затем общий проверенный релиз для установки и оценки пользователем. Это не разрешение выпускать непроверенный snapshot; обязательные проверки пакета сохраняются. Обычный Git через HTTPS/SSH, SSH/Remote SSH, workspaces, контейнеры и виртуальные окружения сохраняются. Локальные документы/ресурсы и запрет ненужных автоматических загрузок остаются в работе. Детальные требования GitHub ниже сохраняются как отложенный проект, а не текущая задача. Облачный backup не возвращается.


## Отложенные требования GitHub и действующие правила локальных ресурсов

Позднейшее решение владельца от 6 ноября 2026 заменяет отмену GitHub login/catalog: нужен вход в GitHub и отдельное окно доступных репозиториев, включая приватные. Облачный backup не возвращать. Корень локальных копий пользователь выбирает один раз; структура <корень>/<владелец>/<репозиторий>. Проверять только этот корень и соответствие Git remote: существующую корректную копию открывать, отсутствующую клонировать и открывать только после успеха. Не перезаписывать конфликтующие папки; учитывать отмену, частичный clone, path traversal и symlink escape. Токены хранить в системном secret storage, исключить их из настроек и логов, запрашивать минимальные разрешения.

Сохранять сеть Git/GitHub HTTPS/SSH, API каталога и входа, Git-команды терминала, SSH/Remote SSH, виртуальные окружения, контейнеры и workspaces. Не блокировать сеть дочерних процессов глобально. Документацию, release notes и ресурсы пользователь скачивает сам и добавляет локально: исключить автоматические загрузки Markdown и внешних стилей, видео и картинок, в том числе ссылки на ресурсы внутри локальных файлов. Ручное открытие ссылки в браузере не разрешает фоновые загрузки. Старую проблему личных идентификаторов владелец отложил: не писать в GitHub Support и не переписывать историю.

Прежние записи об отмене входа/каталога ниже отражают историю и заменены этим решением. Реализация ещё не завершена. Интегратор ведёт назначения в docs/agent-reports/integration-after-local-0.0.9.md; release-notes-local-only уже интегрирован в main: локальный документ открывается явным действием без загрузки удалённого Markdown. Проверки нового native пакета ещё предстоят.

## PDF: пользовательский сценарий

Реализованный MVP documents-ui: пользователь выбирает «Новый документ» или открывает текстовый файл как документ, пишет ответы `а)1`, `б)3` или эссе обычным текстом, выбирает шрифт/размер/интервал и нажимает видимую кнопку «Экспорт PDF». Первый экспорт открывает стандартный диалог сохранения; перезапись подтверждается штатным способом. TeX, установка движка и подключение к интернету не нужны.

Первый MVP: `.txt`, UTF-8, абзацы и переносы без потерь, Unicode/кириллица/английский, выделение и вставка, undo/redo, поиск средствами доступного редактора, сохранение через VS Code document API. Визуальная оболочка документа — опциональный custom text editor, не замена редактора кода. Набор текста не требует Markdown. Параметры страницы относятся к экспорту; не сохранять их в сам текст и не обещать перенос этих параметров между устройствами без отдельного формата.

PDF: A4, поля, основной шрифт из ограниченного набора, размер и межстрочный интервал, автоматические переносы страниц, выделяемый/копируемый текст. Не преобразовывать весь документ в изображение. Нужны случаи на одну и несколько страниц; длинные строки и ручные номера ответов не должны обрезаться.

За рамками первого MVP: полная замена Pages, DOCX, плавающие изображения, сложные таблицы, совместное редактирование, формы PDF, обязательная грамматическая/AI-проверка. Следующая версия может добавить форматированный документ и Markdown/Mermaid/math export после выбора модели хранения и проверки сохранения без потерь. Библиотека документации Go/других языков — отдельная функция чтения/каталога, не часть этого редактора.

## Порядок интеграции

1. Зафиксировать назначения task-id и отдельные checkout/worktree от нашего main. Не выполнять checkout веток в общем каталоге.
2. Готовый PDF backend и новый UI взаимодействуют по контракту `document-export-contract.md`. Предложение изменения контракта передаётся интегратору; оба потребителя должны быть согласованы до объединения.
3. Backend уже в main; объединить UI и его регистрацию в built-in allowlist/build. AI cleanup можно объединить независимо после проверки терминала. MCP audit не разрешает автоматически массовое удаление кода.
4. Интегратор просматривает diff и приватность, выполняет нужные lint/tests/typecheck на общем дереве. Не переносить артефакты out/node_modules из task-веток.
5. После объединения всех запланированных изменений пакета — один общий production bundle/package. Не собирать отдельный релиз после каждой задачи. Native smoke: запуск/сохранение редактора, completion, ручной formatter, Git, zsh/bash, shell Task с exit0, ручной VSIX install→update→uninstall; отсутствие удалённых AI-команд. На пустой языковой поставке Tasks должны продолжать работать.
6. PDF smoke: набрать/сохранить/переоткрыть текст; export/cancel/ошибка записи; русский и английский, несколько страниц. Проверить извлечение текста и визуальную раскладку страниц, отсутствие сети и второго браузерного runtime. Для создания/инспекции PDF использовать доступный PDF skill, если среда его предоставляет.
7. Packaging privacy guard; deep signing → ASAR refresh → outer signing без deep → verify; аудит ZIP. Объединить проверенные изменения в main обычным merge/fast-forward без force. При PR убедиться, что он действительно merged. Не отправлять PR в Microsoft.
8. Опубликовать prerelease для проверенного пакета изменений приложения, проверить релизный тег/исходный коммит и checksum asset. Документационные изменения не требуют нового бинарного релиза или перепаковки ради SHA; main может содержать более новые документы, чем исходный коммит релиза. Повторный цикл нужен только после изменений, влияющих на сборку/проверки, либо по обоснованному исключению из AGENTS.md. Перенести статус в план и обновить краткий отчёт продукта.
