# Контракт экспорта документов v1

Статус: согласованный интерфейс для параллельной разработки, реализация пока отсутствует. Владелец изменений — integration. MVP экспортирует обычный текст; Markdown/HTML не интерпретируются.

```ts
interface DocumentPdfRequestV1 {
  version: 1;
  text: string;
  suggestedFileName: string; // Только имя, без каталога; backend нормализует.
  page: {
    size: 'A4';
    marginMm: number; // 10–30
    fontFamily: 'sans-serif' | 'serif' | 'monospace';
    fontSizePt: number; // 10–24
    lineHeight: number; // 1–2
  };
}
type DocumentPdfResultV1 =
  | { status: 'saved'; uri: string }
  | { status: 'cancelled' };
```

Команда workbench: `myself.documents.exportPdf`. Extension вызывает `vscode.commands.executeCommand<DocumentPdfResultV1>(...)`. Это внутренний контракт нашего продукта, не изменение публичного vscode.d.ts. Cancel не ошибка. Остальные ошибки возвращаются отклонённым Promise и показываются UI понятным сообщением без содержимого документа в логах. Если команда ещё не подключена, UI сообщает об отсутствии backend; не имитирует успешно созданный PDF.

Пустой документ можно экспортировать как пустую страницу. Ограничение v1: UTF-8 текст до 2 MiB; явная ошибка при превышении. Все поля и пределы проверяются на доверенной стороне, не только в webview. Нельзя передавать произвольный HTML, JavaScript, путь для чтения, URL или команду shell. `text` вставляется как текст с экранированием; переносы строк и ручные метки ответов сохраняются. Название файла нормализуется и получает `.pdf`.

Backend открывает стандартный Save Dialog с родителем — текущим окном. Конечный путь берётся только из результата диалога; штатная обработка перезаписи. Запись PDF безопасна при отмене/ошибке; временные файлы принадлежат приложению и удаляются. В MVP не сохранять последний путь и не перезаписывать PDF молча по повторному нажатию.

Рендеринг локальный на существующем Electron printToPDF. Отдельное короткоживущее offscreen/hidden окно, ограниченные права, без Node в документе, без remote content и внешних ресурсов; сетевые обращения и навигация блокируются. Шрифты и CSS контролирует приложение. Окно/сессия и таймеры закрываются при успехе, отмене, ошибке и timeout. Одновременно один экспорт на окно приложения, без постоянного фонового renderer. Персональные документы и содержание не попадают в telemetry/logs.

Предполагаемые настройки по умолчанию: A4, поля20mm, serif12pt, интервал1.5. Конкретное отображение единиц и адаптация к Electron API — ответственность pdf-export. Тесты должны проверять переносы, Unicode, текстовый слой, разрывы страниц, отмену и ограничения входа.

Пути backend: `src/vs/platform/documentExport/**`, workbench adapter: `src/vs/workbench/contrib/documentExport/**`. Команда/IPC/service wiring в существующих общих файлах — integration. Backend передаёт точный список нужных подключений в своём отчёте.

Справочные первичные источники: [Electron webContents.printToPDF](https://www.electronjs.org/docs/latest/api/web-contents#contentsprinttopdfoptions), [Custom Editors API](https://code.visualstudio.com/api/extension-guides/custom-editors). Версии API сверять с зависимостями нашего checkout; не обновлять Electron ради функции.

Внешние страницы при подготовке плана были недоступны; ссылки даны как справочные, а не как результат проверки их текущего содержания. Реализацию сверять с локальными типами/API и фактической версией Electron в нашем checkout.
