# Nerded Code — задание на визуал Calmer Studio

Дата решения: 6 ноября 2026. Статус: дизайн выбран пользователем; реализация и проверка в приложении ещё требуются. Это спецификация для следующего пакета, не отчёт о готовом UI.

## Зафиксированный выбор пользователя

- Рабочее имя приложения: **Nerded Code**. Calmer Studio — название выбранного визуального направления, не имя приложения.
- Основа: **Calmer Studio · Оригинал**. Пользователь отдельно выбрал оригинал после сравнения глубины и затем цветные значки.
- Файлы и папки: **цветные vscode-icons**, полный набор типов. Монохромный вариант отклонён. Служебные кнопки остаются спокойными монохромными.
- Спокойный тёмный интерфейс, слегка тёплый основной текст, лавандовый акцент, пастельная подсветка кода. Код — главный визуальный центр.
- Небольшие скругления, ощущение цельности и иерархии поверхностей. Без крупных округлых карточек, тяжёлых теней, стекла и декоративной анимации.
- Собственная иконка приложения и маскот пока НЕ выбраны. Ранее обсуждавшиеся глаза, буквы, персонажи и названия не являются заданиями на реализацию.

## Локальные референсы и приоритет

1. [calmer-studio-icons.html](design/references/calmer-studio-icons.html): выбран **второй** вариант `Цветные · vscode-icons`, контейнер `.product.studio.colorful` в `#calmer-icons`. В исходном файле он имеет `hidden`, потому что выбор хранился в оболочке просмотра; это не означает, что выбран первый монохромный вариант.
2. [calmer-studio-depth.html](design/references/calmer-studio-depth.html): выбран **первый** вариант `Calmer Studio · Оригинал`, `.product.studio` в `#calmer-depth`. Мягкие слои / Приподнятый / Утопленный / Тёплая глубина — только архив сравнения, не новые требования.
3. [calm-editor-directions.html](design/references/calm-editor-directions.html): первоначальные варианты; из них выбран Calmer Studio.

Копии референсов сохранены без изменения байтов. Это HTML-фрагменты из просмотрщика, а не готовое расширение и не автономный продукт: карусель, Lucide и Tweak могли предоставляться оболочкой. Для просмотра выбранного варианта можно сделать отдельную рабочую обёртку, не менять архивные файлы. Цветные SVG внутри icon-макета встроены как data URI. Не переносить демонстрационный JavaScript в IDE.

При расхождении: явный выбор пользователя → эта спецификация → выбранный вариант макета → общая дизайн-система. Числа ниже извлечены из макета; инженерные рекомендации и значения для первого прохода отдельно помечены. Не трактовать все старые варианты как одновременно утверждённые.

## Компоновка

- Верх: компактная полоса с переключателем рабочей папки/проекта, кнопкой скрытия файлов и штатными оконными контролами. Название приложения Nerded Code показывать в предназначенных для имени продукта местах, не подменять им имя открытой папки.
- Слева: одно дерево файлов с цветными иконками; компактный видимый поиск/переход к файлу; внизу доступ к обычному Git (ветка и реальные изменения). Не оставлять постоянный широкий столбец декоративных/неиспользуемых activity icons. Сохранять доступ к нужным функциям через понятные меню.
- В центре: вкладки, редактор, номера строк. Активная вкладка и файл различимы, но не выглядят яркими баннерами. Не делать капсульные вкладки и большие поля вокруг редактора. Minimap и breadcrumbs не показывать по умолчанию в новом пресете; возможность пользователя настроить их сохраняется.
- Снизу: терминал с небольшой шапкой, переключением сессий, скрытием/показом и изменяемой высотой. Это настоящий терминал, не имитация HTML-строк.
- Нижняя строка: компактные сведения и доступ к терминалу. Состояния сохранения, Git, ошибок и подключения брать из существующих сервисов, не рисовать постоянное «Сохранено» или счётчик из макета.
- Sidebar и terminal сворачиваются и меняют размер; размеры сохраняются через штатный механизм layout. Длинные имена обрезаются с доступным полным именем; на узком окне панели не перекрывают код.
- Файлы `main.go`, `worker.rs`, `app.ts`, `config.py`, папки `src/assets`, проект `fieldnotes`, хост `dev-server` — только демонстрационные данные. Они не должны появиться в приложении пользователя.

### Граница функций первого пакета

Действующие ограничения AGENTS.md сохраняются: первый пакет локальный; Remote SSH/server и GitHub login/catalog отложены. Надпись `SSH · dev-server` в макете не разрешает их подключить. В локальном режиме убрать её; будущий remote-индикатор должен отображать только настоящее подключение после отдельной интеграции. Ручные git/ssh в терминале сохраняются. Не возвращать Command Palette, AI, Sessions и другие удалённые функции ради демонстрационных контролов. Для нужных действий использовать доступные меню/кнопки и уже сохранённый файловый поиск.

## Палитра выбранного макета

HEX — эталон значений новой темы/пресета, а не разрешение рассыпать литералы по общим CSS. Сопоставить существующим theme color IDs; новые регистрировать только при необходимости. Для light/high-contrast и пользовательских тем сохранять штатные переопределения.

| Роль | Значение |
| --- | --- |
| Редактор и терминал | `#101010` |
| Верхняя полоса, sidebar, status bar | `#151515` |
| Тонкие разделители | `#282828` |
| Основной текст | `#E6E2DD` |
| Вторичный текст и комментарии | `#A39CA9` |
| Основной акцент и terminal prompt | `#C9B7F3` |
| Ключевые слова | `#E8B4D9` |
| Функции | `#B9DDFC` |
| Строки | `#D8C7F1` |
| Номера строк | `#77717E` |
| Hover/спокойное выделение строки в макете | `#FFFFFF0C` поверх поверхности |

Иерархия строится на разнице поверхностей, отступах и выделении активного элемента. Акцент используется дозированно. Не окрашивать все кнопки/файлы фиолетовым. Цвета ошибок, предупреждений, diff, selection, terminal ANSI и focus должны оставаться семантически различимыми; макет не задаёт их полный набор, поэтому дополнить штатными theme tokens и проверить читаемость. Реальную тему пользователя не перезаписывать: макет задаёт отдельный согласованный пресет.

## Геометрия и текст

| Элемент | Из макета | Перенос в приложение |
| --- | --- | --- |
| Верхняя полоса | 48 px | Согласовать с нативным titlebar и зоной перетаскивания |
| Sidebar | 202 px | Стартовый ориентир около 200–220 px, затем resize пользователя |
| Строка файла | 30 px | Ориентир обычной плотности; сохранить доступную compact-настройку |
| Полоса вкладок | минимум 43 px | Около 40–44 px, штатные метрики табов и hit targets |
| Status bar | 32 px | Компактный, без обрезки items и split controls |
| Иконка файла | 16 × 16 px | Сохранить размер/цвет оригинального SVG |
| UI font | system sans, 13 px | Штатные роли UI, без загрузки веб-шрифтов |
| Code font | system monospace, 14 px; line-height 1.85 | Начальный ориентир; не менять пользовательский editor font/lineHeight |
| Terminal font | system monospace, 13 px; line-height 1.8 | Согласовать с настоящей сеткой терминала и настройками пользователя |
| Отступ кода | 24 px сверху, 22 px сбоку | Сопоставить существующей шкале отступов, не ломать gutter/selection/minimap |

Высота 570 px у макета и 136 px у терминала — размеры демонстрации, не жёсткие ограничения приложения. Не переносить мобильные media queries макета как контракт desktop layout.

В макете кнопки имеют radius 5 px, меню 8 px, внешняя демонстрационная рамка 10 px. Инженерный перенос: Control/Inner/Outer tiers существующей дизайн-системы (обычно 4/6/8 px), без крупных капсул. Округление всей картинки не означает вложенные закруглённые карточки редактора. Нативную рамку окна не дублировать. У исходного выбранного редактора нет выраженной тени/парящего острова: не подменять его вариантом Raised. Тени допустимы у меню/диалогов; глубину основных панелей получить разницей фонов.

## Иконки

- Использовать настоящий полный набор **vscode-icons**: файловые расширения/имена, специальные папки, закрытое/открытое состояние, fallback для неизвестных файлов. 10 демонстрационных SVG из HTML не заменяют набор.
- Подключать через существующий file icon theme mechanism. Цвета SVG не обесцвечивать filter/mask/currentColor и не заменять монохромными Codicons. Служебные кнопки закрытия, поиска, Git, панели могут использовать существующие Codicons.
- Перед упаковкой проверить идентификатор темы, версию, лицензию и attribution используемого набора. Хранить ресурсы локально в поставке; никакой автозагрузки расширения/CDN при первом запуске. Не включать языковые расширения ради иконок.
- Не генерировать новый набор значков и не создавать логотип приложения в рамках этой задачи.

## Плавность и производительность

Пользователь просил ощущение плавности и цельности, но не выбрал конкретный тайминг. Рекомендация первого прохода: короткие transitions порядка 100–140 ms для hover/focus/fill, только если они помогают распознать состояние. Открытие файла, ввод и терминальный вывод не задерживать. Уважать reduced motion. Не анимировать каждый resize, каждую строку дерева и печать; не использовать `transition: all`, бесконечные эффекты, backdrop blur/vibrancy и полнооконные тяжёлые тени. В покое оформление не должно запускать таймеры, новые процессы или сетевые запросы.

## Как внедрять в существующий форк

1. Прочитать AGENTS.md, актуальные claims и [development-plan.md](development-plan.md). Не занимать файлы другого работающего агента. Разделение ниже — предлагаемые задачи, не назначение владельцев.
2. Использовать существующие `src/vs/workbench/contrib/modernUI/`, theme services и layout. `appearanceActions.ts` уже предоставляет выбор Classic/Modern; `textSizeActions.ts` — настройки размеров. Не создавать второй engine или webview-оболочку вместо настоящего workbench.
3. Учесть, что текущий Modern UI использует connected/pill tabs, floating-card gutters и frosted glass. Включение одного `workbench.experimental.modernUI` НЕ реализует выбранный Calmer Studio. Настроить отдельный пресет/ограниченный scope, сохраняя действующие режимы и тесты; отключить стекло в Calmer.
4. Цвета оформить как тему/пресет; геометрию применять только в выбранном режиме. Новый чистый профиль поставки должен показывать согласованный вариант. В существующем профиле обеспечить видимое применение через Appearance без молчаливого перезаписывания пользовательских шрифтов, темы и размеров при каждом старте.
5. Рабочее имя Nerded Code подключает интегратор через product/build metadata и пользовательские строки. Не делать массовую замену `myself` в идентификаторах, путях данных, URL schemes, storage keys или extension IDs. Смена технических идентификаторов и миграция данных — отдельное решение. Папку репозитория не переименовывать.
6. Оставить штатные services для save/dirty, tabs, Git, terminal, меню, drag/drop, клавиатуры и доступности. Упрощение chrome не должно удалять необходимое поведение.

Агент ведёт собственный `docs/agent-reports/<task-id>.md`. После целевых проверок передаёт изменения интегратору. Общий build/package только в составе накопленного пакета; отдельная запись этого ТЗ сборки не требует.

## Критерии приёмки

- [ ] На чистом профиле настоящий Nerded Code визуально соответствует Calmer Studio Original с цветными vscode-icons; не monochrome/raised/inset/warm/graphite.
- [ ] Файлы слева, переключение папки, вкладки, Git, терминал и нужные меню доступны; нет AI-панели, декоративной activity rail, фиктивного SSH-хоста и лишней домашней страницы.
- [ ] Палитра из таблицы подключена через тему; ошибки, diff, выделение, focus и ANSI читаемы. Цветные иконки работают для разных языков и неизвестных типов.
- [ ] Открытие/закрытие и переключение файлов, dirty/save/undo, resize/split editor, toggle sidebar/terminal, длинные имена и переполнение вкладок работают без скачков/обрезания.
- [ ] Проверены масштаб UI, keyboard-only навигация, high contrast, reduced motion, сохранение настроек существующего профиля и повторный запуск.
- [ ] Снимки реального приложения при 1440×900 и 1024×768: дерево + два файла + терминал; отдельно меню/hover/focus и split. Это размеры для проверки, не обязательный размер окна пользователя.
- [ ] Целевые theme/modernUI/configuration tests и lint по изменениям пройдены. CSS-тесты используют реальный CSS; пустой CSS-loader не доказывает геометрию.
- [ ] Перед общим пакетом интегратор проверил настоящий UI/native smoke, отсутствие автоматической сети и сохранение существующих security/trust требований. HTML-макет не считается доказательством работающего приложения.

## Что передать интегратору

Список изменённых файлов и точек подключения, выбранные theme/icon IDs и версии, результаты целевых проверок, снимки реального UI, отличия от макета с объяснением, статус оставшейся интеграции. Работу не объявлять завершённой только потому, что появились новые CSS или тема без подключения.
