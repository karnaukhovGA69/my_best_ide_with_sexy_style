## Ограничения первого пакета для личного тестирования

Последнее уточнение владельца: первый пакет — локальный редактор. Автоматические обращения в Интернет исключены, включая Git autofetch, обновления, телеметрию, загрузку документации/подресурсов и фоновые каталоги. Обычный системный Git и ручные git/ssh в терминале сохраняются; сеть допустима по явному действию пользователя. Это не сетевой sandbox для произвольных команд или сторонних расширений.

Remote SSH/удалённый сервер редактора и новую автоматизацию удалённых окружений не включать в первый минимальный релиз; существующий код/наработки сохранить. Это временное ограничение поставки заменяет прежнюю активную интеграцию Remote SSH, а не удаляет ручной ssh. GitHub login/catalog/root-clone остаются отложенными.

Сохранить Workspace Trust и запрет автоматического запуска задач/терминала из недоверенных проектов; не ослаблять Electron sandbox, CSP, TLS/SSH verification. Перед новым релизом проверить готовое приложение: untrusted workspace не запускает код автоматически, локальная документация не загружает внешние ресурсы, запуск/простой без действий пользователя не инициируют сеть. Прежние smoke с --disable-workspace-trust этого не доказывают и не заменяют проверки. Состояние реализации этих требований фиксировать отдельно, не объявлять их выполненными только из-за записи в плане.


## Текущий приоритет: редактор и пользовательское тестирование

Последнее решение владельца от 6 ноября 2026: собственный GitHub-вход, подключение аккаунта, специальный каталог репозиториев, выбор корня и clone/open по кнопке ОТЛОЖЕНЫ до пользовательского тестирования редактора. Это заменяет прежнее поручение реализовывать их сейчас. Не продолжать разработку/подключение этих функций к ближайшему релизу, не регистрировать OAuth app и не запрашивать Client ID. Сделанное сохранить в отдельной task-ветке со статусом «отложено по решению владельца»; не удалять и не выдавать за готовую авторизацию. Не добавлять extensions/myself-github в allowlist/build текущего релизного пакета.

Приоритет: остальные согласованные функции обычного редактора и стиль/UI, затем общий проверенный релиз для установки и оценки пользователем. Это не разрешение выпускать непроверенный snapshot; обязательные проверки пакета сохраняются. Обычный Git через HTTPS/SSH, SSH/Remote SSH, workspaces, контейнеры и виртуальные окружения сохраняются. Локальные документы/ресурсы и запрет ненужных автоматических загрузок остаются в работе. Детальные требования GitHub ниже сохраняются как отложенный проект, а не текущая задача. Облачный backup не возвращается.


## Отложенные требования GitHub и действующие правила локальных ресурсов

Позднейшее решение владельца от 6 ноября 2026 заменяет отмену GitHub login/catalog: нужен вход в GitHub и отдельное окно доступных репозиториев, включая приватные. Облачный backup не возвращать. Корень локальных копий пользователь выбирает один раз; структура <корень>/<владелец>/<репозиторий>. Проверять только этот корень и соответствие Git remote: существующую корректную копию открывать, отсутствующую клонировать и открывать только после успеха. Не перезаписывать конфликтующие папки; учитывать отмену, частичный clone, path traversal и symlink escape. Токены хранить в системном secret storage, исключить их из настроек и логов, запрашивать минимальные разрешения.

Сохранять сеть Git/GitHub HTTPS/SSH, API каталога и входа, Git-команды терминала, SSH/Remote SSH, виртуальные окружения, контейнеры и workspaces. Не блокировать сеть дочерних процессов глобально. Документацию, release notes и ресурсы пользователь скачивает сам и добавляет локально: исключить автоматические загрузки Markdown и внешних стилей, видео и картинок, в том числе ссылки на ресурсы внутри локальных файлов. Ручное открытие ссылки в браузере не разрешает фоновые загрузки. Старую проблему личных идентификаторов владелец отложил: не писать в GitHub Support и не переписывать историю.

Прежние записи об отмене входа/каталога ниже отражают историю и заменены этим решением. Реализация ещё не завершена. Интегратор ведёт назначения в docs/agent-reports/integration-after-local-0.0.9.md; release-notes-local-only уже интегрирован: release notes открываются из локального документа по явному действию.

Сводка на 6 ноября 2026 года для нового чата или отдельного агента. Не нужно перечитывать всю переписку. Сначала прочитай этот файл, затем AGENTS.md, своё задание и актуальный git status. Документы описывают состояние на дату записи; текущую готовность проверяй по коду и отчётам.

## Идея и границы

Владелец хочет собственную IDE на основе уже существующего форка Code - OSS: меньше лишних функций/кнопок и фоновой аналитики, новые документы/справка/перенос настроек через файл и позже другой UI. Рабочее имя Myself IDE. Репозиторий: https://github.com/karnaukhovGA69/my_best_ide_with_sexy_style. Не начинать новый форк, не трогать оригинальный VS Code/baseline и не fetch/merge/push upstream. Работать только с текущими наработками; origin — репозиторий владельца.

Не путать упрощение с полным переписыванием редактора. Не обещать меньший RAM/быстродействие без замеров. Полный каталог решений: [project-plan.md](project-plan.md).

## Ключевые договорённости переписки

- Убираем встроенные Copilot/AI/Chat/Sessions/MCP/voice и аналитику. Обычный IntelliSense (методы после точки, типы, параметры, диагностика) нужен.
- Публичная поставка без предустановленных языковых расширений, но с Git/Markdown/темами/служебными builtins. Extension host/API, Open VSX, VSIX и ручное обновление сохраняем. Не удалять пользовательские расширения и не обещать совместимость со всем Marketplace.
- Персонально владелец хочет Rust, C++, F#, Lua, Go, Docker, YAML, JSON, SQL. Это локальная установка, не состав GitHub-релиза. Позднее общее правило языков перекрывает ранние отдельные галочки L01–L18.
- Обычные Git/SSH и общий authentication API, терминал/Tasks, настройки и обычные инструменты разработки остаются. Grunt/Gulp/Jake не нужны; Tasks не удалять вместе с ними.
- Удалить пользовательский мультикурсор, встроенный format-on-save, палитру команд, Sticky Scroll, рекомендации и автообновления расширений. Новые функции обязаны иметь доступные кнопки/меню. Не вырезать API, необходимое сохраняемым сценариям, без анализа потребителей.
- Локальная история файлов/проектов/терминала остаётся. Локальные warning/error логи нужны для ремонта; не отправлять их автоматически. Цель — небольшой объём без постоянного тяжёлого сборщика.
- Позднейшее решение от 6 ноября: GitHub login/catalog нужны по контракту выше, backup не нужен. Настройки переносим локальным файлом без секретов и автоматической перезаписи.
- Каталог GitHub должен открывать или клонировать репозитории только в выбранном корне; обычные Git и SSH сохраняются.
- Библиотека документации: локальные Markdown/PDF, справка IDE/языков, просмотр рядом с кодом; загрузка справочников позже.
- Документы: обычный текст учебных ответов/эссе → PDF видимой кнопкой, без TeX/облака. Полная замена Pages не требуется в первом MVP.
- Терминал: исследовать Ghostty/другой движок; встроить отдельное приложение простым профилем shell нельзя обещать. Если дорого — штатный терминал с настройками/shell-плагинами, затем внешняя интеграция.
- Визуальный ремастер: свой бренд/эмблема, форма кнопок, панели, цвета, настраиваемая плотность/скругления. Calmer Studio и бренд включены в локальный 0.0.10; остальные платформы требуют отдельной приёмки.
- Основные результаты должны попадать в origin/main, а не оставаться в phase-ветках. Публичную историю не переписывать. Использовать GitHub noreply и существующие privacy guards; старые приватные идентификаторы не повторять в отчётах. Новое обращение в поддержку для удаления старого кэша пользователь не просил.
- Полный build/package/smoke/release делать на пакет изменений. Не после каждого коммита, завершения агента или сообщения «дальше». Документы — без сборки; на коде целевые проверки. См. AGENTS.md.

- Фильтры distributionRuntime и production entrypoints исключают Sessions/Agent Host/local transcription и ряд AI SDK. Общие AI/MCP исходники/контракты и зависимости остаются.
- Телеметрия/IDs/эксперименты/crash upload заблокированы. Рекомендации и автообновления расширений не запускаются; ручной каталог/VSIX/update работает.
- Inline Chat и Terminal Chat больше не регистрируют основные контроллеры/действия. Совместимые сервисы отключены; регистрации оставшихся terminal chat tools удалены в восьмом этапе.
- Пользовательские действия палитры/мультикурсора/Sticky Scroll/format-on-save убраны. Snippet suggestions и Welcome отключены по умолчанию; не весь исходный код удалён.
- Tasks исправлены для поставки без языковых расширений: пустые pattern/matcher registries инициализируются при регистрации расширений, shell task завершается.
- Native logs: warning/error по умолчанию, 2 MiB + 4 backup на канал, ротация при записи в новый UTC-день; часть старых файлов очищается после 7 дней. Дополнительно реализован best-effort бюджет архивных сеансов 100 MiB при старте с сохранением текущих/недавних/неполных сеансов. Это не жёсткая квота всех живых логов/Output/расширений.
- PDF implementation: src/vs/platform/documentExport/**, src/vs/workbench/contrib/documentExport/**. NativeHost/desktop entrypoint уже подключены. Extension DTO: myself.documents.exportPdf; команда видимой кнопки: myself.documents.exportActiveTextPdf. Контракт в document-export-contract.md.
- PDF: текущий буфер → native Save Dialog → локальный Electron printToPDF → атомарная запись. A4/20mm/serif12pt/1.5, лимит 2 MiB UTF-8, экранирование текста, sandbox/без сети и JS, временное окно и cleanup. Markdown/HTML печатаются буквально. Опциональный documents-ui добавляет New Document/Open as Document, поиск, save/undo/redo и настройки страницы. Эти параметры живут только в текущем редакторе.

## Проверки и известные ограничения

Для восьмого этапа прошли полный client typecheck, 281 автоматический тест, целевой lint, native smoke IDE и документов, native PDF cancel/concurrency/write failure/cleanup, визуальная и текстовая проверка PDF на 1 и 6 страниц. Финальный пакет проверен на Git, bash/zsh, Tasks, completion, ручной formatter и VSIX install/update/uninstall. Подпись, ASAR и ZIP privacy/CRC audit прошли; tag и digest проверены.

Один обычный профиль при ручном запуске показал пустое окно. Причина не установлена; изолированный профиль успешно открыл файл и экспортировал PDF. Не объявлять это исправленным и не сбрасывать пользовательский профиль без причины. macOS ARM64 — проверенная платформа; приложение ad-hoc signed, не notarized. Другие ОС/SSH не проверены. Вход и каталог GitHub возвращены в план, готовность реализации ещё не подтверждена. Не заявлять, что весь AI физически удалён или все сторонние расширения лишены сетевых запросов.
