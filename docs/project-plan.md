Локальный Nerded Code для macOS ARM64 собран из `3dbf0296716432e7d6e3d61196a71865ccb7ad7c`. Проверены production package, ad-hoc подпись, ASAR/ZIP и отсутствие build paths. Обычный запуск без --user-data-dir открыл прежний профиль Myself IDE и не изменил settings.json; папки не перемещались. Это не сетевой sandbox и не доказательство совместимости всех расширений.

Полный состав, границы повторных проверок и SHA-256 — [nerded-release-package.md](agent-reports/nerded-release-package.md). PDF-читатель библиотеки, общий полнотекстовый индекс, общий бюджет логов и полное удаление оставшегося AI-кода не завершены. GitHub login/catalog и Remote SSH/server остаются отложенными.

## Ограничения первого пакета для личного тестирования

Последнее уточнение владельца: первый пакет — локальный редактор. Автоматические обращения в Интернет исключены, включая Git autofetch, обновления, телеметрию, загрузку документации/подресурсов и фоновые каталоги. Обычный системный Git и ручные git/ssh в терминале сохраняются; сеть допустима по явному действию пользователя. Это не сетевой sandbox для произвольных команд или сторонних расширений.

Remote SSH/удалённый сервер редактора и новую автоматизацию удалённых окружений не включать в первый минимальный релиз; существующий код/наработки сохранить. Это временное ограничение поставки заменяет прежнюю активную интеграцию Remote SSH, а не удаляет ручной ssh. GitHub login/catalog/root-clone остаются отложенными.

Сохранить Workspace Trust и запрет автоматического запуска задач/терминала из недоверенных проектов; не ослаблять Electron sandbox, CSP, TLS/SSH verification. Перед новым релизом проверить готовое приложение: untrusted workspace не запускает код автоматически, локальная документация не загружает внешние ресурсы, запуск/простой без действий пользователя не инициируют сеть. Прежние smoke с --disable-workspace-trust этого не доказывают и не заменяют проверки. Состояние реализации этих требований фиксировать отдельно, не объявлять их выполненными только из-за записи в плане.


## Текущий приоритет: редактор и пользовательское тестирование

Последнее решение владельца от 6 ноября 2026: собственный GitHub-вход, подключение аккаунта, специальный каталог репозиториев, выбор корня и clone/open по кнопке ОТЛОЖЕНЫ до пользовательского тестирования редактора. Это заменяет прежнее поручение реализовывать их сейчас. Не продолжать разработку/подключение этих функций к ближайшему релизу, не регистрировать OAuth app и не запрашивать Client ID. Сделанное сохранить в отдельной task-ветке со статусом «отложено по решению владельца»; не удалять и не выдавать за готовую авторизацию. Не добавлять extensions/myself-github в allowlist/build текущего релизного пакета.

Приоритет: остальные согласованные функции обычного редактора и стиль/UI, затем общий проверенный релиз для установки и оценки пользователем. Это не разрешение выпускать непроверенный snapshot; обязательные проверки пакета сохраняются. Обычный Git через HTTPS/SSH, SSH/Remote SSH, workspaces, контейнеры и виртуальные окружения сохраняются. Локальные документы/ресурсы и запрет ненужных автоматических загрузок остаются в работе. Детальные требования GitHub ниже сохраняются как отложенный проект, а не текущая задача. Облачный backup не возвращается.


## Отложенные требования GitHub и действующие правила локальных ресурсов

Позднейшее решение владельца от 6 ноября 2026 заменяет отмену GitHub login/catalog: нужен вход в GitHub и отдельное окно доступных репозиториев, включая приватные. Облачный backup не возвращать. Корень локальных копий пользователь выбирает один раз; структура <корень>/<владелец>/<репозиторий>. Проверять только этот корень и соответствие Git remote: существующую корректную копию открывать, отсутствующую клонировать и открывать только после успеха. Не перезаписывать конфликтующие папки; учитывать отмену, частичный clone, path traversal и symlink escape. Токены хранить в системном secret storage, исключить их из настроек и логов, запрашивать минимальные разрешения.

Сохранять сеть Git/GitHub HTTPS/SSH, API каталога и входа, Git-команды терминала, SSH/Remote SSH, виртуальные окружения, контейнеры и workspaces. Не блокировать сеть дочерних процессов глобально. Документацию, release notes и ресурсы пользователь скачивает сам и добавляет локально: исключить автоматические загрузки Markdown и внешних стилей, видео и картинок, в том числе ссылки на ресурсы внутри локальных файлов. Ручное открытие ссылки в браузере не разрешает фоновые загрузки. Старую проблему личных идентификаторов владелец отложил: не писать в GitHub Support и не переписывать историю.

Прежние записи об отмене входа/каталога ниже отражают историю и заменены этим решением. Реализация ещё не завершена. Интегратор ведёт назначения в docs/agent-reports/integration-after-local-0.0.9.md; release-notes-local-only уже интегрирован в main: локальный документ открывается явным действием без загрузки удалённого Markdown. Новый native пакет проверен в указанном выше объёме; подробности и ограничения — в nerded-release-package.md.

Сводка решений с обновлением от 6 ноября 2026 года. Название Myself IDE рабочее; репозиторий — `karnaukhovGA69/my_best_ide_with_sexy_style`. ## Цель

Сделать собственную настраиваемую IDE на основе уже созданного форка Code - OSS: проще по интерфейсу и составу, с полноценными инструментами разработки, без встроенного AI-блока и аналитики. Добавить удобные документы, локальную справку и перенос настроек через файл. Облегчение должно затрагивать загружаемый код и состав поставки, а не только скрывать кнопки. Снижение размера, RAM и времени запуска — цели, которые ещё нужно измерить отдельно.

Нового редакторного движка с нуля не пишем. UI можно менять постепенно в существующей архитектуре. Electron и совместимость расширений пока остаются основой; радикальное переписывание проекта не согласовано.

## Оставляем

- Файлы/папки, Explorer, несколько проектов и окон, поиск/замену, навигацию, undo/redo, autosave, восстановление и полезную локальную историю. Штатную защиту при работе с большими файлами сохраняем.
- Подсказки существующих методов/полей/типов, hover, параметры функций, диагностику, переходы, переименование и рефакторинг. Языковые возможности предоставляет установленное пользователем расширение; их API не вырезаем вместе с AI.
- Расширения и extension host/API, ручную установку/обновление, собственные расширения, форматтеры и линтеры. Каталог сейчас Open VSX; ручной VSIX обязателен. Полную совместимость со всеми расширениями Microsoft не обещаем.
- Обычные Git-операции, SSH, локальные репозитории и общий API аутентификации расширений. Вход в GitHub и каталог репозиториев требуются; облачный backup исключён.
- Терминал, bash/zsh, shell integration, историю, splits, shell-плагины, Tasks и npm scripts. Готовые интеграции Grunt/Gulp/Jake убираем; сам механизм Tasks оставляем.
- SSH и инфраструктуру удалённой разработки, отладку, Test Explorer и покрытие. Наличие кода не равно проверенной доступности каждого сервиса в форке.
- Настройки, горячие клавиши, профили, темы, вкладки, панели, локализацию, Zen Mode. Markdown, Mermaid, математику, media preview, notebooks, webviews/custom editors и браузерные поверхности.
- Локальные технические логи и Output для диагностики, без автоматической отправки. Process Explorer нужен для поиска нагрузки.

## Порядок работы

1. Продолжать независимую очистку по текущим claims и завершить согласованные функции обычного редактора и UI/style. Documents/PDF/settings portability уже проверены в локальном пакете 0.0.9; новые source изменения перечислены в integration-after-local-0.0.9.md.
2. Локальная документация и ресурсы: release-notes-local-only и библиотека HTML/Markdown/TXT уже интегрированы; продолжить PDF/локальные наборы и проверки отсутствия внешних ресурсов отдельными зарезервированными задачами. Сохранять IntelliSense, extension API, Git, терминал и Tasks.
3. Подготовить общий пакет для пользовательского тестирования: объединённые проверки, production package, native smoke ключевых сценариев, подпись/privacy audit и публикация при доступном авторизованном CLI. Проверенный локальный 0.0.9 не обозначать как содержащий последующие source изменения.
4. Терминальные улучшения, библиотека локальной документации, общий бюджет логов и визуальный ремастер — самостоятельные задачи с точными scopes. Не менять пользовательские профили и личный языковой набор автоматически.
5. GitHub login/account/catalog/root-clone/open отложены до тестирования редактора пользователем. Сохранить отдельную task-ветку, не подключать её к текущему пакету и не запрашивать OAuth Client ID.

Это порядок по зависимостям, без обещаний сроков. Независимые области можно делать параллельно. Один агент владеет одной областью, интегратор — общими файлами и релизом. Несколько изменений накапливаем в пакет; один общий build/test/release. Между ними только необходимые целевые проверки. Новая реплика «дальше» не требует нового релиза.
