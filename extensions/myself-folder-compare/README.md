# Folder Comparison

An optional local extension for Nerded Code. It is not part of the default application bundle. Runtime dependencies are zero; TypeScript compiles to CommonJS using the repository's existing compiler.

In the Files header overflow choose **Compare Two Folders…**, or use the comparison button in the **Folder Comparison** view in Explorer. Select the left folder, select the right folder, then confirm **Compare**. Neither picker cancellation nor opening the view starts a scan. Multi-root workspaces do not select a root on your behalf. Restricted Mode permits this explicit read-only operation; no workspace code, hooks or configuration are interpreted.

Results use paths relative to the selected roots. **Added on Right** means absent on the left, **Removed from Right** means absent on the right. **Changed** compares complete file bytes, even when size and timestamps match. File/directory conflicts are reported without descending into the conflicting subtree. Empty added/removed directories are included. Skips and limits make a comparison incomplete and are never treated as equality or proof of absence.

Click a text result to open the standard diff editor with immutable, read-only snapshots. The left and right panes represent the bytes read during that comparison, not live files or unsaved editor buffers. No merge, restore, copy, save or Git action is offered. Binary content containing NUL or invalid UTF-8 is compared as bytes, with no text preview. UTF-16 is not a text-preview format in this MVP. Snapshot URIs contain random IDs, not source paths. Unknown snapshots after reload are unavailable and never trigger disk reads.

Each comparison allows at most 4,000 directory entries across both trees, depth 8 (root depth 0; directories at depth 8 are not opened), 4 MiB per file and 32 MiB of raw file content across both sides. Reads use chunks of at most 64 KiB, concurrency is one, and elapsed time is checked between I/O operations with a 20-second budget. Entries include skipped links and errors. Result rows are bounded by the entry budget plus one limit/error summary. A limit reached at an enumeration boundary conservatively marks the directory incomplete, even if it might have ended at that boundary. One byte is reserved for a bounded EOF probe, so files whose reported size equals a byte limit are conservatively skipped; underreported content is not classified as equal. Cancel stops further work at the next checkpoint; operating-system I/O is not a hard-deadline operation.

At most 16 snapshot pairs are retained. Open snapshots from earlier comparisons share the 32 MiB raw-content budget with new scans. Close old diff tabs to release them. A new comparison clears old result rows but preserves open snapshots unchanged until their documents close. Buffer decoding, IPC and editor models make extra copies; the raw-content budget is not a process-memory or editor-model limit. A cancelled scan publishes no partial results.

Only native absolute file paths without authority/query/fragment are accepted from the two folder pickers. Remote windows are unsupported. Symlinks, ancestor symlinks, junctions and nonregular files are skipped. Selected symlink roots are not followed. Identical and nested roots are allowed within the same limits. File mounts and hardlinks are not a physical-locality or isolation guarantee. This MVP requires POSIX no-follow/nonblocking file flags; Windows returns an explicit unsupported result instead of silently weakening the file-open policy.

The scanner checks path components and canonical paths, opens regular files with `O_NOFOLLOW | O_NONBLOCK`, checks file-descriptor identity before reading and checks version/identity afterwards. Node's path-based directory operations are **not an atomic sandbox against another writer replacing an ancestor between checks**. Detection discards affected content, but cannot undo a read or enumeration already performed during such a race. Use stable folders for comparisons. This is an observed snapshot, not an atomic snapshot of both complete trees. The extension itself makes no network calls, launches no processes and writes nothing to selected folders. Standard editor events may still be observed by other installed extensions.

## Development and later local installation

With the repository dependencies already available, run `pnpm --dir extensions/myself-folder-compare test` from the repository root. Compilation uses the existing TypeScript compiler. Tests use Node 24 built-ins, `.cts` stripping and temporary fixtures, without VS Code or additional test dependencies.

For a later approved local VSIX smoke, compile with `pnpm --dir extensions/myself-folder-compare compile`, then use an already available VSCE tool to package this directory with `vsce package --no-dependencies`; do not download a packager automatically. Inspect the archive for only the manifest, localization, license, README and `out/*.js`, then install the VSIX manually into an isolated disposable profile. This task does not package, install or modify the owner's profile and does not add the extension to any application allowlist.

Native smoke should cover visible Files/header navigation, both picker cancellations, confirmation cancellation, additions/removals/equal-length changes, links/errors/limits, cancellation during a scan, binary results, repeated comparisons with old snapshots open, closing snapshots, read-only diff panes, no changes to source files, Restricted Mode and a remote window refusing the operation.
